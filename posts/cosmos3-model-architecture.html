01 / SYSTEM MAP

The generator is a latent-flow model wrapped around a VLM.

02 / MODALITY ENCODERS

Four inputs, four adaptation rules.

“Token” does not always mean an integer vocabulary ID. Vision, sound, and action tokens are continuous vectors placed into Transformer sequence slots.

TXT

Text · discrete

The prompt is formatted with the VLM chat template, tokenized, and embedded by the language model. BOS/EOS and a start-of-generation marker define the understanding split.

IDs [Ntext]embedding [Ntext, H]
prompt→token IDs→embed_tokens
RGB

Image / video · continuous grid

RGB tensors are normalized to [−1,1], compressed by the video VAE, spatially patchified, and projected. Images use T=1; videos retain a compressed temporal grid.

pixels [C,T,H,W]latent [48,T′,H′,W′]patch 2×2 → 192
RGB→VAE→2×2 patches→vae2llm
ACT

Robot action · continuous timestep

A timestep is one token. Its native vector is normalized, padded to 64 channels, and projected using weights selected by the robot embodiment’s domain ID.

native [T,D]model [T,64]1 token / step
physical vector→normalize + pad→DomainAwareLinear
AUD

Audio · continuous timeline

Waveform audio is channel-adjusted and compressed by AVAE to a latent timeline. Each latent instant becomes one sequence token, projected with sound2llm.

wave [C,N]latent [Csound,T′]1 token / latent step
waveform→AVAE→sound2llm

03 / ACTION UNIFICATION

Different embodiments share width, not semantics.

Cosmos3 preserves each dataset’s action meaning. It standardizes tensor width and model interface, while domain_id selects embodiment-specific input/output projections.

Choose native layout

10D cartesian: xyz + rot6d + gripper.

The first D channels are real. Channels D…63 are model-only zeros. After sampling, the saved action is sliced back to D and denormalized.

04 / SEQUENCE PACKING

Concatenation has two meanings.

The Transformer sequence includes text and modality slots. Separately, the ODE sampler flattens only generated continuous states. Their orders agree after text is excluded.

Transformer pack[text][vision][LiDAR][action][sound][EOG]Every item gets a hidden-state slot and 3-axis position IDs.
Sampler state[vision | LiDAR | action | sound]One flat vector is advanced by the flow solver and split back by recorded shapes.
Temporal-causal option[text][A₀,V₀][A₁,V₁]…[sound][EOG]Actions prefix each visual supertoken; default Nano config leaves this option off.

05 / ATTENTION DESIGN

Two pathways, one asymmetric mask.

The default two_way rule gives generation tokens full context without allowing future/generated content to leak backward into causal language reasoning.

U

Understanding tokens use the normal Q/K/V/O projections and causal self-attention.

G

Generation tokens use separate *_moe_gen projections and attend to every UND and GEN key in their own sample.

×

Variable-length offsets isolate packed samples. Optional multiview FlexAttention can further restrict the GEN→GEN quadrant.

Conditioning is not a third attention type. Clean and noisy vision/action/audio tokens occupy the generation split. A separate condition mask decides which latent positions remain fixed and which receive timestep embeddings, loss, noise, and velocity.

06 / 3D MULTIMODAL RoPE

Position is a coordinate, then a rotation.

Each token gets three IDs—time, height, width. Qwen’s rotary module interleaves axis-specific frequency bands and rotates Q/K; it does not add a learned position vector to the token.

Inspect coordinates

Video: T-major 3D grid

Within each latent frame, height and width enumerate the patch grid. The same temporal ID repeats across all spatial patches.

time / T
height / H
width / W
position(token) = (temporal_offset + t, h, w)
flatten order = t → h → w
StreamPosition IDsCross-modal timing
Text(i, i, i)Monotonic; a large configured margin separates text from media time.
Vision(offset + scaled_t, h, w)VAE temporal compression and FPS determine real-time spacing.
Action(vision_offset + scaled_t, 0, 0)Frame-rate tokens; action[0] defaults to vision frame 1.
Audio(vision_offset + scaled_t, 0, 0)AVAE latent rate—often 25 Hz—aligns to the vision clock; sound[0] aligns to frame 0.

08 / FLOW + OUTPUTS

The Transformer predicts change, not the final sample.

At each solver step Cosmos3 predicts modality velocities. The sampler updates one flat continuous state, then each modality’s codec reverses preprocessing.

Vision

Latent → pixels

  1. llm2vae predicts patch velocity.
  2. Sampler integrates toward clean latent.
  3. Unpatchify and video-VAE decode.
  4. Map [−1,1] to RGB and write JPG/MP4.
Action

64D → native controls

  1. llm2action[domain] predicts velocity.
  2. Mask fixed, invalid, and padded channels.
  3. Slice from 64 back to native D.
  4. Invert dataset normalization and write JSON.
Audio

Latent → waveform

  1. llm2sound predicts latent velocity.
  2. Sampler integrates the audio timeline.
  3. AVAE decodes waveform samples.
  4. Optional mux combines sound and video.
