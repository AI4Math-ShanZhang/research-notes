02 / MODALITY IDENTITY

What is modality_embed, and how large is it?

Is it another token, a positional embedding, or the mechanism that makes every raw modality the same width?

Direct answer. It is one learned vector of shape [hidden_size] for a modality. After a raw modality is projected to the language-model width, this same vector is broadcast-added to every token in that stream. It marks what kind of token this is; it does not store time or spatial position.
raw tokens [N, Dmod] → modality projection → [N, H] + modality_embed [H] → [N, H]
Size ledger
one vector
There is no sequence axis: shape is exactly [H].
Nano / 8B
H = 4096, so one modality vector contains 4,096 learned numbers.
other widths
2B: 2,048 · 4B: 2,560 · 32B: 5,120.
broadcast
PyTorch expands [H] across all N modality tokens during addition.
Correct order
1Projectnative channel width → H
→
2Add identity+ modality_embed[H]
→
3Position Q/KmRoPE later, inside attention

03 / SOUND INPUT

If images contain pixels, what does sound contain?

What is the waveform’s input format, what does repeat(2, 1) do, and how does sound reach the Transformer?

Direct answer. Sound begins as sampled air-pressure amplitude: waveform: [C_audio, N_samples]. The value at each sample is a floating-point amplitude, normally near [-1, 1]; its horizontal coordinate is time because sample n occurs at n / sample_rate seconds.
[C, N]Waveform48,000 values per second per channel
→
[1, 2, N]Batch + stereomono is copied into L and R
→
[1, 64, T]AVAE encodeSTFT real/imag features → continuous latent
→
[T, 64]Pack timelineone continuous sound token per latent step
→
[T, H]sound2llmproject, then optionally add sound identity
Concrete 10-second example
48 kHz stereo
[2, 480,000] → AVAE, hop 1920 → [64, 250]
then transpose for packing → [250, 64]

Unlike text, these 250 items are continuous latent vectors, not integer vocabulary IDs.

What each line means
repeat(2, 1)
Copy a mono row once so the AVAE receives two channels. It does not double duration.
unsqueeze(0)
Add batch dimension: [2,N] → [1,2,N].
encode
Compress samples to 64-channel audio latents at 25 latent steps/second.
squeeze(0)
Remove only the batch dimension: [1,64,T] → [64,T].

04 / PHYSICAL ROTATION

Why do LIBERO actions have 7D, 10D, or 13D?

Are these different robot commands, or different numeric descriptions of the same command?

Direct answer. They describe the same semantic command—translation, rotation, gripper—but store rotation differently. A run chooses one rotation representation; the action is not always converted to 6D.
7D

7D = 3 position + 3 axis-angle + 1 gripper

xyz · 3axis-angle · 3g
10D

10D = 3 position + 6 rot6d + 1 gripper

xyz · 3rot6d · 6g
13D

13D = 3 position + 9 rot9d + 1 gripper

xyz · 3matrix · 9g
Same orientation, different coordinates
NameStored numbersInterpretationWhy use it?
axis-angle[rx, ry, rz]Direction is the axis; vector length is the angle in radians.Compact and matches the LIBERO simulator command.
rot6d[c₁, c₂]First two columns of a rotation matrix; the third is reconstructed.A smoother representation for neural regression.
rot9dflatten(R₃×₃)All nine entries of the rotation matrix.Direct but redundant; validity can be projected back to SO(3).

06 / SIMULATOR RETURN PATH

How does a 10D model output become LIBERO’s 7D command?

Does the system “reverse” the rotation, and are position or gripper changed too?

Direct answer. Only the numeric rotation representation changes: rot6d → matrix → axis-angle. Position stays three numbers; gripper stays one number. This is deterministic geometry, not a learned decoder and not an inverse physical rotation.
[10]Model actionxyz₃ + rot6d₆ + grip₁
→
[3] [6] [1]Splittranslation · rotation · gripper
→
[3×3]Rebuild Rtwo columns + cross product + SO(3) normalization
→
[3]as_rotvecaxis direction × angle
→
[7]LIBERO stepxyz₃ + rotvec₃ + grip₁
Identity-rotation example
rot6d [1,0,0, 0,1,0]
→ matrix diag(1,1,1)
→ axis-angle [0,0,0]

The result means “no rotational delta.” It does not mean that a matrix was flattened back to arbitrary three Euler angles.

What “axis-angle [3]” means

v = axis × angle. Its direction is the rotation axis; its norm ||v|| is the angle. SciPy’s as_rotvec() performs matrix → axis-angle conversion.

Not Euler XYZ: both use three values, but the three numbers have different meanings.

07 / QWEN 3D mRoPE

How does each modality receive positional information?

What coordinates are assigned, how are the frequency bands interleaved, and where are Q and K actually rotated?

Direct answer. Packing assigns every token a coordinate triple (t,h,w). Qwen converts those coordinates into rotary phases, interleaves temporal/height/width frequency bands, computes cosine and sine, then rotates the query and key features inside attention. mRoPE is an operation on Q/K—not another vector added to the token embedding.

videot h w3D latent grid, flattened in T-major then H then W order.
actiont+1 0 0A (T,1,1) grid; default start offset 1 aligns an action with the transition into the next frame.
soundt 0 0A (T,1,1) grid at the AVAE latent rate; start offset 0.
position_ids [3,B,N] × inverse frequencies → phases
interleave bands with mrope_section = [24, 20, 20] → cos, sin
Q′ = Q·cos + rotate_half(Q)·sin    K′ = K·cos + rotate_half(K)·sin

08 / COORDINATE BOUNDARY

What is temporal_offset, and why 15,000?

Is it a delay, 15,000 empty tokens, a mask, or a physical timestamp—and was the value actually 150,000?

Direct answer. temporal_offset is a running coordinate cursor used while building mRoPE position IDs. Cosmos3’s Nano/Edge/Super recipes add a 15,000 position margin after text—not 150,000—before generation modalities begin. It does not insert 15,000 tokens.
cursor 0begin sampleThe cursor resets independently for each packed sample.
0 … L−1text positionsEach token consumes one ordinary position.
+ 15,000coordinate gapNo embeddings or attention rows are allocated here.
L + 15,000vision startThis value is saved as the shared generation origin.
shared originaction + soundThey reuse the vision start, with their own time rates and start-frame offsets.
What the margin changes
text ↔ gen
It changes their relative rotary phase, creating a clear coordinate boundary.
gen ↔ gen
A common shift preserves relative time among aligned vision, action, and sound streams.
sequence length
Unchanged. Position values jump, but token count and attention-mask size do not.
runtime clock
It is not seconds or frames; FPS scaling maps modality time into rotary coordinates.
Why exactly 15,000?

The local code documents the value as the boundary between text and vision, but does not derive the exact number mathematically.

Therefore the defensible answer is: it is a trained configuration hyperparameter chosen to separate the coordinate ranges. Use the checkpoint’s value. Changing it only at inference would change rotary phases relative to training.

Do not over-interpret it: 15,000 is neither 15,000 frames nor 15,000 padding tokens.

09 / TWO VISUAL ENCODERS

Why does one video go through SigLIP2 and another through Wan VAE?

The support demonstration and the live camera frame are both images. Why are they encoded by different models, and where do they meet?

Direct answer. The two videos have two different jobs. The DROID support video is there to be understood, so it goes through SigLIP2 and becomes semantic tokens in the AR context. The live RoboLab observation is there to be continued, so it goes through the Wan VAE and becomes a latent the model can denoise into future frames and actions. They are never concatenated into one video; they meet only inside the unified Cosmos transformer.
