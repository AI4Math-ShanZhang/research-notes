Parallel Decoding Distillation — one network call for several denoising steps

Paper: Neta Shaul, Chao Liu, Arash Vahdat & Julius Berner (NVIDIA), July 2026, arXiv:2607.26004 · project page (FastGen-PDD). Notes from working through it — the paper part, then the questions that actually made it click.

📄 Paper Summary

The problem. Diffusion and flow models need many sampling steps, and each step is one full forward pass of a 14B–22B transformer. Video generation is therefore slow. The usual fix is to distill the model into a few-step student with variational score distillation (VSD) or an adversarial loss — DMD2 and friends. Those work, but they are hard to optimize and they mode collapse: every prompt starts giving back the same picture, and videos lose their motion.

The claim. You do not need any of that. PDD trains a few-step student with one plain MSE regression loss. No GAN, no second score network, no JVP (Jacobian-vector product), no finite differences. It matches or beats the adversarial methods at 4–8 network calls and keeps far more diversity.

The one-sentence idea. Give the model several output heads. One look at the current state produces the velocities for the next L denoising steps at once — including steps whose states do not exist yet. So one network call moves you L steps instead of one.

Setup and notation

t          time along the path,  t = 0 is pure noise, t = 1 is the image
X_k        the STATE at time t_k  — the noisy image/video latent itself
v_k        the VELOCITY for the interval [t_k, t_k+1] — the arrow you move along

            X_k+1  =  X_k  +  (t_k+1 - t_k) * v_k

N          number of grid intervals   (128/64 for images, 256/128 for video)
L          block size — how many intervals one network call covers
NFE        number of function evaluations = number of network calls = N / L

Architecture

The student reuses the teacher's backbone unchanged and copies the final linear layer N times — one head per grid interval. Head k owns interval [t_k, t_k+1]. The head index is the time conditioning, so no extra time embedding is needed, and the block size can be changed freely.

v_k  =  W_k · H(X_n)          all heads read the SAME backbone features H(X_n)

Because every head is linear on the same features, at inference the L heads are pre-added offline into one matrix:

X_n+1 = X_n + Δt·(v_0+v_1+v_2+v_3)
      = X_n + (Δt·(W_0+W_1+W_2+W_3))·H(X_n)
      = X_n + W_fused · H(X_n)                 ← ONE linear layer
So a PDD network call costs exactly the same as a teacher call. The extra heads exist only during training. You are not buying speed with more compute per call — you are simply making N/L times fewer calls.

Training

flowchart TD A["sample a state X_n on the path
(or pure noise — data-free)"] --> B["ONE student forward pass
→ v_0 … v_L-1"] B --> C["pick a random position k
walk forward with v_0…v_k-1
(free — no network calls)"] C --> D["state X̄_k
stop-gradient"] D --> E["TEACHER at X̄_k
Euler = 1 call · Midpoint = 2 calls"] E --> F["loss = ‖ v_k − teacher_velocity ‖²"] B --> F

Worked out with N = 8, L = 4, step size 0.125, and the sampled position k = 2:

1.  one student pass on X_0                  →  v_0, v_1, v_2, v_3
2.  X̄_1 = X_0  + 0.125 · v_0                  (free, no network call)
    X̄_2 = X̄_1 + 0.125 · v_1                  (free, no network call)
3.  stop-gradient on X̄_2
4.  ask the TEACHER for the right velocity at X̄_2, time t = 0.25
5.  loss = ‖ v_2 − teacher_velocity(X̄_2) ‖²

cost per training step = 1 student pass + 1 or 2 teacher passes

Head 2 is being told: given where heads 0 and 1 actually dragged us, say what the teacher would say there. The heads are trained along the student's own trajectory, so their errors stay consistent with each other instead of piling up.

  • Why stop-gradient? Otherwise the gradient flows back through v_1, v_0 and the whole chain — expensive and unstable. With it, each head is a plain independent regression.
  • Why only one k per iteration? Building X̄_k is free, but teacher calls are not. Sampling one random k costs 1–2 teacher passes instead of L. Over many iterations every head gets trained.
  • Why that still teaches the whole block. All heads share the backbone, so the gradient from head k also improves the features heads 0, 1, 3 read from. The paper argues these gradients recover the full-interval mean-velocity signal in expectation — which is how it avoids ever differentiating the velocity field.
  • Data-free. For the big models they never touch a real image or video. Only text prompts. The student rolls out its own trajectory online and the teacher supervises point by point.
  • Variable NFE for free. L is sampled between L_min and L_max during training, so one trained model samples at 2, 4, or 8 steps with no retraining.

Ablations worth remembering

  • Midpoint beats Euler everywhere. Two teacher calls per training step instead of one, and it estimates the interval average velocity rather than the instantaneous one. Worth the cost.
  • The two hyperparameters that matter most are the time reparameterization (shift) and the batch size. Big batches matter.
  • For Wan they skip one backbone layer for the unconditional CFG branch (layer 10 for 1.3B, layer 12 for 14B), which improved guidance.

🖊 My Key Notes

1. X versus v — the thing to get straight first

X is where you are. v is which way you move. Same tensor shape, completely different role.

what it ismeaning
X_ka state, a pointthe noisy picture at time t_k
v_ka velocity, an arrowdirection + speed to move during [t_k, t_k+1]
X_0 --v_0--> X_1 --v_1--> X_2 --v_2--> X_3 --v_3--> X_4

tiny example (pretend an image is 2 numbers, step = 0.125):
  X_0 = [ 1.0, -2.0 ]     v_0 = [ 4.0, 8.0 ]
  X_1 = X_0 + 0.125·v_0 = [ 1.5, -1.0 ]
  v_1 = [ 2.0, 8.0 ]
  X_2 = X_1 + 0.125·v_1 = [ 1.75, 0.0 ]

Watch the index: v_1 is not "the velocity of X_1". It is the arrow used at X_1, which lands you on X_2. And in PDD it is computed from X_0, not from X_1. That mismatch is the whole method.

2. Classical decoding vs parallel decoding

Classical (the teacher). One network call = one step. The network must be fed X_3 before it can say the direction at X_3. Strictly sequential.

X_0 -[CALL 1]-> X_1 -[CALL 2]-> X_2 -[CALL 3]-> X_3 -[CALL 4]-> X_4
    -[CALL 5]-> X_5 -[CALL 6]-> X_6 -[CALL 7]-> X_7 -[CALL 8]-> X_8

8 steps  →  8 network calls

PDD, L = 4. One network call = L steps. One look at X_0, four arrows out.

                one look at X_0
                      |
      +-------+-------+-------+
      v       v       v       v
     v_0     v_1     v_2     v_3       ← 4 directions at once
      \       |       |       /
       +------+---+---+------+
                  v
X_0 -[CALL 1]------------------> X_4
X_4 -[CALL 2]------------------> X_8

8 steps  →  2 network calls
Where the efficiency comes from, exactly: classical = N calls, PDD = N/L calls. The network is a 14B–22B transformer, so one call dominates everything. Adding vectors and the fused linear layer are basically free. Cutting 8 calls to 2 cuts wall-clock by about 4×. LTX-2.3: 120 calls → 8.

3. The word "parallel" is not about GPUs

It does not mean more devices, or several samples at once. It means several future denoising steps are decoded from one forward pass — the same shape as speculative / multi-token decoding in an LLM (Medusa-style heads), where extra heads guess the next few tokens the model has not seen yet. Here they guess the next few denoising directions.

Why different heads? Why not one head applied L times?

One head reading H(X_0) gives the same vector every time, so X_4 = X_0 + 0.5·v — a single big Euler step, a straight line. The noise-to-image path is curved, so you cut the corner and land off it. L different heads draw a 4-segment polyline that can bend and follow the curve. Same cost, much better shape.

Then why not just run the network L times with the same head?

You could — that is the teacher. It costs L network calls, which is exactly the slowness being attacked. The whole point is 1 call per block instead of L.

Are the L outputs X_n+1, X_n+2, X_n+3 …?

No. They are the sub-intervals inside block n. Only their sum connects X_n to X_n+1:

X_n+1 = X_n + Δt·(v_0 + v_1 + v_2 + v_3)

n indexes blocks, k indexes positions within a block. At inference the intermediate states X̄_1, X̄_2, X̄_3 are never built — you just add the arrows. They only exist during training, where you need them so you can ask the teacher "what is the right arrow at this exact spot?"

4. The obvious objection, and the answer

"Why not just take 2 big steps with the original teacher? That is also 2 calls."

true path (curved):     X_0 ..----..
                                  '.
                                    '..____ X_8

teacher, 2 big steps:   X_0 --------------->   straight, cuts the corner, lands off

PDD, 2 calls:           X_0 --\
                               \--\
                                   \--\____   4 bends per call, follows the curve

Asked at X_0, the teacher reports the direction at that exact point. Move 0.5 along it and you fly off the curve. PDD's heads answer a different question: from X_0, what are the four directions that keep you on the curve? Head 1 reports the direction at a point it has never seen, because in training it was regressed against the teacher's answer at that future point.

Split the two things. The speed comes purely from making N/L times fewer calls. The quality comes from training the heads to fill in the shape between calls. Both cost nothing extra at run time.

5. Why the training is so cheap

PDD           :  1 student pass + 1–2 teacher passes per step
trajectory RL :  full teacher rollout
VSD / DMD2    :  student + second trainable "fake score" net + discriminator

That is why 200 iterations were enough for Wan 14B and ~250 for LTX-2.3 22B. Simple regression also means no adversarial balancing act — the paper reports stable convergence across hyperparameters, which is the actual selling point over GAN/VSD, more than the raw numbers.

6. Why the diversity gap is the interesting result

VSD and adversarial losses push the student toward high-likelihood outputs. That is why DMD2 wins HPSv2 and PickScore — those metrics reward one polished image. It is also exactly why diversity halves: the student collapses onto the modes the reward likes. In video this shows as less motion, which is the VideoMAE/V-JEPA columns.

PDD regresses onto the teacher's own trajectory, so it inherits the teacher's spread by construction. It is a trajectory-matching method, not a reward-maximizing one.

7. Limitations

  • Loses on human preference. DMD2 is a point ahead on HPSv2 at both 4 and 8 NFE. The paper's defence is that this is bought with mode collapse, which is fair, but if you only ship one image per prompt the user may not care.
  • Not the winner on ImageNet 1-step. FreeFlow's 1.45 FID beats PDD's 2.69 by a wide margin. The method's case rests on the large-model regime.
  • N heads is N extra output matrices during training. With N = 256 for video and a 22B model, the memory cost of the head bank is not discussed in detail. It vanishes at inference, but training-time cost is real.
  • No ablation on the loss itself. No "without stop-gradient" row, no comparison of teacher approximation order beyond Euler vs Midpoint, no isolation of what the shared backbone actually contributes versus the heads.
  • Still teacher-bounded. Trajectory distillation can at best reach the teacher. It cannot exceed it, which reward-based distillation sometimes appears to do on preference metrics.
