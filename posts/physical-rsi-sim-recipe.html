Toward Recursive Self-Improvement in Physical AI — what AI coding improves, and why it (doesn't) count as RSI

Paper: Toward Recursive Self-Improvement in Physical AI — Meng Luo, Zechen Bai, Shanqing Xu, et al. (NUS, HUST, SJTU, NTU, HKBU), Oct 2026, arXiv:2610.29677 · project page · awesome list. This note covers what an AI coding agent can change in simulator training (the simulator or the training recipe), and why updating weights is not what makes something RSI.

📄 Paper Summary

What kind of paper

A survey / position paper (~62 pages + appendix). It proposes no new method and runs no experiments. Its only new "method" is the design of a test for recursion (Sec. 4.4), which it leaves to future work.

Definition

Recursive self-improvement (RSI) = a system improves not only its behavior but also the process by which it improves. The paper splits the system into two roles:

  • Learner — the robot's policy / world model / memory. It gets updated.
  • Improver — the part that revises the learning procedure (often an LLM coding agent).

Where a change is stored (Fig. 1)

  1. Policy   2. World model   3. External knowledge (memory, skills, code) → change what the robot does
  2. Learning procedure (what data to collect, how to judge it, how to update) → changes how it learns. Physical RSI starts here.

Ladder of claims

ClaimMeaningRecursive?
Behavioral improvementthe robot does the task betterNo
Later-learning benefitthe change makes later learning easierNo
Procedure improvementthe learning recipe itself gets betterNo
R1lessons from past repairs make the improver better at the next repairYes
R2the improved improver helps produce its own next improvementYes

Four conditions for gains to carry forward

  1. Feedback addresses what the learner still lacks (sensing shows only part of a failure).
  2. The receiving component can use the change (on its body).
  3. The value survives task or hardware change (wear, drift, gripper swap).
  4. Continued practice stays safe and affordable.

Main finding

Existing studies (mostly manipulation) support the first three claims. Some systems change the improver's knowledge or tools (HARBOR, AURA, ENPIRE, PhysEvo), but no physical study isolates a gain caused by recursion. That needs a comparison against the same improver with its acquired knowledge frozen, on new failure types.

🖊 My Key Notes

For AI coding with the simulator, what can the AI improve: the simulator or the training recipe?

An LLM coding agent writes or edits code around the simulator. The physics engine itself (Isaac, MuJoCo) usually stays fixed. The agent changes what goes into it and how training runs:

What the AI changesExample systemConcretely
Reward functionEureka, CARDwrites reward code ("+1 forward speed, −0.1 torque"), reads training stats, rewrites
Physics randomization rangesDrEurekapicks "friction 0.3–1.5, mass ±20%" so the policy survives on the real robot
Tasks / environmentsGenSim, RoboGen, Eurekaversewrites new simulated tasks or terrains, harder each round but still learnable
CurriculumAURAstand → walk → step over obstacles, each stage with its own reward and settings
Hyperparameters / RL settingsHARBOR, AURAlearning rate, PPO settings, etc.
Simulator setupHARBORbuilds the sim scene, then reward, then tuning, through gated sub-agents
Digital twinD-Worlda frozen LLM edits the twin after each real action; keeps the edit only if prediction error drops (one edit: 22.4 → 1.5 mm)
Training code / infrastructureENPIREedits training and policy code, runs real robot trials, keeps or drops each idea; safety / reset / checking code is locked
Its own toolsPhysEvoa meta-agent edits the task agent's tools and its own diagnostic tools
Mostly the training recipe (reward, randomization, curriculum, settings, code). Sometimes the simulator content (scenes, tasks, digital twin). Not the physics engine.
Why does this count as RSI — because the model improves or its weights are updated?

Weight updates are not what makes it RSI. There are two different models in the loop:

  • Learner = robot policy. Its weights are updated by RL. That is just training.
  • Improver = LLM coding agent. Its weights are usually frozen.
Level 1  policy weights updated, recipe fixed           → normal learning          (not RSI)
Level 2  LLM rewrites the recipe (Eureka: reward v1→v2→v3) → procedure improvement   (not recursive:
         the LLM is the same every round — "a fixed outer searcher")
Level 3  the improver itself gets better                → R1 / R2                  (RSI)

The paper says the improver's knowledge can live in weights, memory, code, or prompts (Sec. 3.3). Most current systems keep the LLM frozen and improve through what it writes and keeps:

  • HARBOR — "lessons" from tuning rounds in an experience memory
  • AURA — database of past curricula and feedback (without it, runnable curricula drop 99% → 38%)
  • ENPIRE — written summary of a pin-insertion search reused for GPU insertion
  • PhysEvo — edited tools and skills

Example. HARBOR redesigns the 3-cube-stacking reward in 30 min instead of 4 hours after building memory. Looks like a better improver, but not proven: same task (could be memorization), and no frozen-memory control. The test the paper wants:

Improver with its lessonsSame LLM, memory frozen at round 1
New, unseen failure typefixed in 1 hourfixed in 4 hours

Only a gap on a new failure type against a frozen-knowledge copy counts. The fair control depends on where the knowledge lives: old checkpoint for weights, old snapshot for memory, old version for code / prompts.

If the LLM weights are not updated, isn't it just in-context learning?

Yes, mechanically. With a frozen LLM, the improver's "self-improvement" is in-context learning plus a memory it writes itself. The paper still calls it (possible) RSI because RSI is defined by what gets better, not how. The improver is the whole system:

improver = frozen LLM + memory file + tools + prompts + code

Round 1: fixes a grasp failure, writes "slip → raise friction reward weight first"
Round 2: new slip failure, reads memory, fixes it in 1 try instead of 5
         → weights unchanged, but the system improves faster
Plain ICLPossible RSI (paper)
Knowledgeexamples in one prompt, gone after the episodememory kept and growing across rounds
Written bya humanthe system, from its own trials
Recursive?noonly if lessons make the next lessons better (R1) and the improver then improves its own rules / tools (R2)
This is a weak form of RSI with a ceiling: notes help a frozen LLM use what it already knows, but its basic reasoning never grows. Calling it "ICL with a growing memory" is fair, and the paper admits no robot study has proven even this yet.
