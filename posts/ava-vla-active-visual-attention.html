AVA-VLA — Improving Vision-Language-Action Models with Active Visual Attention

Paper: L. Xiao, J. Li, J. Gao, F. Ye, Y. Jin, J. Qian, J. Zhang, Y. Wu & X. Yu, arXiv:2511.18960 · CVPR 2026. Baseline throughout: OpenVLA-OFT. Written up from a reading session — the questions I actually asked, in order, in plain words.

📄 Paper Summary

One line. Take OpenVLA-OFT, fill its zero action placeholders with a recurrent state, and use that same state to turn each visual token up or down.

OFT:      A_t ~ P(A_t | x_t)              Markov — current observation only
AVA-VLA:  A_t ~ P(A_t | x_t, r_(t-1))     POMDP — plus a belief-like memory

The paper's framing is that a VLA built on a VLM processes dense visual input independently at every timestep, which implicitly treats the task as an MDP. They reformulate it as a POMDP and approximate the belief state b_(t-1) = P(s_(t-1) | x_(<t), A_(<t)) with a learned vector r_(t-1), because the exact belief is intractable.

🖊 Background — what OpenVLA-OFT actually does

Everything in AVA-VLA is a modification of one equation, so it is worth unpacking that equation first.

What does p_t = 0̄ = [0_0, 0_1, …, 0_(L_c−1)] ∈ R^(L_c × D × d) mean?

Symbol by symbol:

  • t — the current control timestep (one decision moment).
  • z_I^t — visual tokens from the cameras.
  • z_S^t — language instruction + robot proprioceptive state.
  • p^t — the placeholder tokens.
  • L_c — chunk length, how many future action steps are predicted at once (8).
  • D — action dimension (7: x, y, z, roll, pitch, yaw, gripper).
  • d — model hidden size (4096).
  • M_parallel — the VLM run in one forward pass, bidirectional attention.
  • Q — the MLP head turning hidden states into real numbers.

So you create L_c × D = 8 × 7 = 56 tokens, each a vector of size 4096. And in OpenVLA-OFT every one of those vectors is all zeros. That is what the equation says: a list of L_c blocks, each block D zero vectors. They are empty seats for actions not yet predicted.

The process:

1. encode images  -> z_I^t
2. encode text + state -> z_S^t
3. make 56 zero placeholder tokens
4. concat: [ z_I^t | z_S^t | p^t ]
5. ONE forward pass, bidirectional attention
6. read the hidden states at the 56 placeholder positions
7. Q maps them to A^t  (8 steps x 7 dims)
8. execute, go to t+1, repeat
The catch the paper is setting up. Since all placeholders are identical zeros, the token content carries zero information. The only thing telling slot 3 apart from slot 40 is the positional encoding. Those 56 slots are free real estate sitting in the sequence doing nothing.
Do z_I and z_S also see each other?

Yes. OFT does not only make the action slots bidirectional — it drops the causal mask for the whole sequence. Its own wording: the model "takes empty action embeddings as input and replaces the causal attention mask with bidirectional attention."

            sees ->   z_I    z_S    p (actions)
  z_I  (images)        v      v        v
  z_S  (lang+state)    v      v        v
  p    (placeholders)  v      v        v

Why it matters. With a causal mask and order [images, language, state, actions], image token 5 sees images 1–4 only — it does not see the language. So the visual features are computed blind to the task. Bidirectional attention lets image tokens attend to the instruction and the state, so visual features become task-aware inside the LLM, and action slots see each other.

Keep separate: inside the vision encoder (SigLIP / DINOv2 ViT) patches were always bidirectional. ViTs never use a causal mask. The change is about the LLM backbone.

Why does the policy see only x_t? Why the Markov assumption?

Five reasons, and only the last is a real argument:

  1. That is how the data is stored. RLDS / Open X-Embodiment / LeRobot dump episodes as flat (observation, action) pairs. Sampling one frame is trivial; a consistent history window is extra work.
  2. Images are expensive. One 224×224 view ≈ 256 tokens; two cameras ≈ 512. Eight history frames = ~4000 extra tokens, and attention is quadratic.
  3. Control must be fast. 10–50 Hz. Long context = slow pass. Speed is exactly what OFT was optimizing, so history works against the whole point.
  4. History often hurts — the copycat problem. Feed past frames or past actions and the model finds a shortcut: next action ≈ last action. Training loss drops, real performance collapses. Known as causal confusion. Many groups tried history, got worse, went back to single-frame.
  5. The theory gives cover. In a fully observed MDP the optimal policy only needs the current state. If you assume the camera sees everything, x_t is enough.

Reason 5 is the weak link, and it is what the paper attacks. Real manipulation is a POMDP:

  • Occlusion — the arm covers the object it is about to grasp.
  • Motion is invisible in one frame — direction and velocity need at least two frames.
  • Task progress is not visible — "put 3 blocks in the box", box closed, did I do 2 or 3?
  • Hidden physical state — is the drawer locked, is the bottle empty, did the grasp fail once?
  • Repetitive scenes — two stages look identical but need different next actions.

In all these, two different correct actions map to the same x_t. A Markov policy can only output the average, which is usually wrong.

🖊 The data pipeline — why "Markov" is really a dataloader artifact

On disk (RLDS / tfrecord shards):

episode_00042  (task: "pick up the red cup", 120 steps)
 |- step 0   : {img_third, img_wrist, state[7], action[7], lang, is_first=1}
 |- step 1   : {img_third, img_wrist, state[7], action[7], lang}
 |- ...
 |- step 119 : {..., is_last=1, is_terminal=1}

Making one batch:

  1. Pick a dataset. Weighted draw over the mixture (Bridge 13%, Fractal 12%, …).
  2. Read an episode. Random shard, 120 steps into memory.
  3. Standardize the action space. Every robot logs differently → [dx, dy, dz, droll, dpitch, dyaw, grip].
  4. Normalize with per-dataset 1st/99th percentile stats: dx = 0.0031, q01 = −0.021, q99 = 0.024 → 2·(0.0031+0.021)/(0.024+0.021) − 1 = 0.071. Everything lands in ~[−1, 1]; gripper stays 0/1.
  5. Chunk the actions. At step 57 gather 57…64 → A_57 = [a57 … a64], shape 8×7. Near the episode end it pads by repeating the last action, with a mask so padding does not count in the loss.
  6. Flatten the episode into loose frames. The episode structure is destroyed — 120 independent samples. Nothing knows sample 57 and 58 came from the same episode.

The shuffle buffer — the "throw out and refill" part. A ring buffer of fixed size (~100,000 frames). It is not "load a batch, use it, delete it". It is a continuously flowing pool: one slot out, one slot in.

fill once (takes minutes):
  buffer = [ 100,000 random frames from many episodes and many datasets ]

steady state, forever:
  1. pick a random index i
  2. emit buffer[i]                 <- goes into the batch
  3. read ONE new frame from the stream
  4. buffer[i] = that new frame     <- slot refilled immediately

batch size 64  ->  do that 64 times  ->  batch #1
                   batch #1: forward, backward, optimizer step, FREED
                   meanwhile a prefetch thread is already building batch #2

Why the buffer must be big: without it a batch would be 64 consecutive frames from one episode, which look nearly identical and give terrible gradients. With 100k, the 64 frames come from ~64 different episodes and several robots. Frames 57 and 58 of episode 42 end up thousands of steps apart.

What one sample looks like at the model input:

images    -> 224x224 -> augment -> SigLIP + DINOv2 -> concat -> project -> 512 visual tokens
language  -> "In: What action should the robot take to pick up the red cup?\nOut:" -> ~24 tokens
state[7]  -> small MLP -> 1 state token
placeholders                                                      -> 56 zero vectors

full sequence = [ 512 visual | 24 text | 1 state | 56 zeros ] = 593 tokens
batch of 64   = [64, 593, 4096]
The point. The Markov assumption is not really a modelling choice someone argued for. It falls out of the pipeline: step 6 throws away episode structure, the shuffle buffer scatters neighbouring frames into far-apart batches, and no state survives between batches. To use history you must change the chunking and flattening steps — which is exactly what AVA-VLA does.

🖊 One image → 8 actions, and what that costs

t=0   camera click  x_0
      ONE forward pass -> a0 a1 a2 a3 a4 a5 a6 a7
      robot executes all 8, eyes closed

t=8   camera click  x_8
      ONE forward pass -> a8 a9 a10 a11 a12 a13 a14 a15
      robot executes all 8, eyes closed

At 30 Hz control, 8 steps ≈ 0.27 s. So the robot looks at the world about 4 times per second, not 30. That is where the speedup comes from — 1 forward pass instead of 8.

Blind inside the chunk. No new input during those 8 steps. Open loop. If a human bumps the cup at step 3, the robot keeps executing the old plan until step 8. Shorter chunk = more reactive but slower; longer = faster but more blind. 8 is the compromise.

Is the next chunk connected to the previous one?

No. When the model predicts a8…a15 at t=8 it does not see a0…a7, does not know it predicted a chunk 0.27 s ago, does not remember x_0. Completely fresh call — same as if the robot had just been switched on at that moment.

chunk 1:  x_0  --> [a0..a7]
                        X          no arrow here
chunk 2:  x_8  --> [a8..a15]

Then why does it work at all? The link exists, but it lives in the physical world, not in the model. Executing a0…a7 moves the arm, so x_8 shows the arm in its new place and the state vector reports new joint angles. The robot's body is the memory. That works as long as the camera really shows everything.

The visible symptom: a small jerk at the chunk boundary. The last action of chunk 1 and the first of chunk 2 came from two independent forward passes; nothing in the loss says "chunk 2 must continue chunk 1". The known fix (ACT / ALOHA) is overlapping chunks + temporal ensembling — predict a new chunk every single step and average the predictions for the same timestep:

at t=0: a0 a1 a2 a3 a4 a5 a6 a7
at t=1:    a1 a2 a3 a4 a5 a6 a7 a8
at t=2:       a2 a3 a4 a5 a6 a7 a8 a9
action sent at t=2 = weighted average of the three predictions for a2

Smooth and reactive, but a forward pass every step throws away the 8× speedup. OFT chose speed.

Why not use a KV cache?

A KV cache pays off only when both hold: (1) many forward passes over a growing sequence, (2) a fixed prefix whose K/V never change.

Original OpenVLA satisfies both — it generates 7 action tokens one at a time, so it caches the 536-token prefix and computes 1 new token per pass. Big win.

OFT does one pass per control step. There is no second pass to save work for. Parallel decoding did not "give up" the KV cache; it made it pointless by removing the thing being sped up.

OpenVLA (AR):     pass1, pass2, ... pass7   <- cache saves 6 recomputes
OFT (parallel):   pass1                     <- nothing to save

And you cannot cache across control steps either:

t=0  [ 512 visual (photo A) | 24 lang | 1 state | 56 slots ]
t=8  [ 512 visual (photo B) | 24 lang | 1 state | 56 slots ]
       ^^^^ all new           same      new       new

The whole point is a new photo — 512 of 593 tokens are new. Only ~24 language tokens repeat (~4%). And the harder blocker: attention is bidirectional, so language tokens attend to image tokens and produce different K/V when the image changes. There is literally no stable prefix. Cacheable prefixes require causality.

Where a KV cache would be the natural memory — keep the old frame's K/V as history:

per timestep of history:
  512 tokens x 32 layers x 2 (K and V) x 4096 dims x 2 bytes (fp16) = 268 MB

4 Hz over a 60 s episode = 240 steps -> ~64 GB of cache, on top of 14 GB of weights.

Dead on arrival. Which is exactly why AVA-VLA compresses it:

full KV cache of history:   268 MB per step, grows forever
AVA-VLA r_(t-1):            56 x 4096 x 2 bytes = 0.46 MB, constant

Same goal — carry the past forward. One is exact and unbounded, the other lossy and bounded. They chose lossy and bounded, and reused the 56 slots that were already sitting there full of zeros, so it costs zero extra sequence length.

🖊 The method — two changes

Change 1 — the placeholders are no longer zeros

OFT:      p_t = all zeros        (L_c x D x d = 8 x 7 x 4096)
AVA-VLA:  p_t = r_(t-1)          same shape, now carries information

Where r_(t-1) comes from — the last-layer hidden states at those same action positions, from the previous timestep, pushed through a 2-layer SiLU MLP (Eq. 5):

r_(t-1) = B( h_M^(t-1) )   in R^(L_A x d),   L_A = L_c * D = 56

The paper's justification: those pre-action hidden states "contain fused visual and language information and are predictive of the agent's intent." At episode start r_(-1) = 0̄.

Change 2 — the Active Visual Attention gate

  1. Down-project vision, language and r_(t-1) to a smaller width d′ (2-layer SiLU MLP per modality; d′ is not stated in the main text).
  2. FiLM the vision with the language: ẑ_I = F_γ(z̄_S) ⊙ z̄_I + F_β(z̄_S).
  3. Cross-attention — vision is the query, the memory is key/value (Eq. 7–9): Q = W_Q ẑ_I, K, V = W_K/W_V r̂_(t-1), O = SelfAtt(CrossAtt(Q, K, V)). Each patch asks "given what I was doing last step, am I relevant?"
  4. Two-way scoring (DynamicViT / LVPruning style): ρ = Softmax(W(FFN(O))) ∈ R^(L_I × 2) — enhance vs weaken.
  5. Collapse to one dial: ω = ρ·γ with γ = [1.9, 0.1], so ω ∈ [0.1, 1.9]. 1.9 = look hard at this patch; 0.1 = mostly ignore it. A soft dial centred near 1 — not pruning.
  6. Inject into every layer's attention (Eq. 11–12): A_ij = exp(C_ij)·U_ij / Σ_l exp(C_il)·U_il, where U is 1 on the diagonal and for non-vision columns, and ω_j for off-diagonal entries whose column j is a vision token.

Full forward pass (Eq. 6):

A^t = Q( M_parallel( z_I^t , V(X^t, r_(t-1)) , z_S^t , r_(t-1) ) )
So r_(t-1) enters twice: once as the content of the 56 action slots ("state-based initialization"), and once as the key/value that drives the visual gate.

🖊 Full tensor walk (LIBERO config: 2 cameras, chunk 8, 7-DoF, B = 1)

Stage 1 — raw images to visual tokens (unchanged from OFT):

raw           third-person [1, 3, 256, 256]   wrist [1, 3, 256, 256]
resize+norm   -> [1, 3, 224, 224] each

SigLIP ViT-SO400M/14 : 224/14 = 16 -> 16x16 = 256 patches
                       [1, 3, 224, 224] -> [1, 256, 1152]
DINOv2 ViT-L/14      : [1, 3, 224, 224] -> [1, 256, 1024]
concat on feature dim                   -> [1, 256, 2176]
projector (2176 -> 4096)                -> [1, 256, 4096]   per view
2 views stacked                         -> [1, 512, 4096]   = z_I

Stage 2 — the other inputs:

language -> tokenizer -> 24 ids -> embed  -> [1,  24, 4096]  = z_S
proprio state (8 numbers) -> MLP         -> [1,   1, 4096]
recurrent state from last step  r_(t-1)  -> [1,  56, 4096]   (zeros at t=0)

Stage 3 — the AVA module:

down-project:
  z_I      [1, 512, 4096] -> MLP -> [1, 512, d']
  z_S      [1,  24, 4096] -> MLP -> [1,  24, d']
  r_(t-1)  [1,  56, 4096] -> MLP -> [1,  56, d']

FiLM:  pooled lang -> F_gamma [1, d'], F_beta [1, d']
       z_I_hat = gamma * z_I_bar + beta        -> [1, 512, d']

cross-attn (vision = QUERY, memory = KEY/VALUE):
  Q [1, 512, d']   K [1, 56, d']   V [1, 56, d']
  Q @ K^T          -> [1, 512, 56]     512 patches x 56 memory slots
  softmax @ V      -> [1, 512, d']

self-attn among patches -> [1, 512, d']  = O
FFN                     -> [1, 512, d']
linear d' -> 2          -> [1, 512, 2]
softmax                 -> [1, 512, 2]   = rho
omega = rho @ [1.9, 0.1] -> [1, 512]     each in [0.1, 1.9]

U -> [1, 593, 593]
  U[i,j] = 1        if j is NOT a visual token
  U[i,j] = 1        if i == j            (diagonal untouched)
  U[i,j] = omega_j  if j is a visual token and i != j       <- varies by COLUMN only

Stage 4 — the LLM with the modified attention:

input = concat([ z_I , z_S , proprio , r_(t-1) ]) = [1, 593, 4096]
                  512    24      1        56

every one of the 32 layers:
  normal:   A = exp(C) / rowsum(exp(C))
  AVA:      A = exp(C)*U / rowsum(exp(C)*U)        C, A -> [1, 32heads, 593, 593]

output -> [1, 593, 4096]

Stage 5 — two heads read the last 56 positions:

h_M = out[:, -56:, :]   -> [1, 56, 4096]

Head A (actions):  MLP  [1, 56, 4096] -> [1, 56, 1] -> reshape [1, 8, 7]
Head B (memory):   2-layer SiLU MLP   [1, 56, 4096] -> [1, 56, 4096] = r_t

Stage 6 — the loop:

t=0:  r_(-1) = 0   ->  A_0 [1,8,7],  r_0     <- identical to plain OFT
t=1:  r_0          ->  A_1 [1,8,7],  r_1
t=2:  r_1          ->  A_2 [1,8,7],  r_2

Cost: 0 extra sequence tokens, 0.46 MB carried, one 512×56 cross-attn + one 512×512 self-attn at width d′, plus an elementwise multiply in each of 32 attention layers.

🖊 Training — the dataloader had to change

OFT:      shuffle buffer -> 64 random frames from 64 random episodes
AVA-VLA:  shuffle buffer -> 64 random WINDOWS, each 4 consecutive frames
          run them in order t=0 -> t=1 -> t=2 -> t=3, carrying r forward
          batch tensor now has a time axis: [64, 4, ...]
  • Truncated BPTT, T = 4. Full BPTT called "computationally prohibitive" for a 7B backbone.
  • Gradient detached between the 2nd and 3rd timestep → two 2-step gradient segments.
  • Loss: per-step action-chunk MAE, plus an L2 gate regularizer L_ω = ‖μ(ω) − c‖ (Eq. 13), total L = ΣΣ (L + λ L_ω) (Eq. 14). Without it the model would just set every ω to 1.9 and ignore the mechanism.
  • Hyperparameters: λ = 1.0, c = 0.6 (LIBERO) / 0.2 (CALVIN, "smaller region of interest"), γ = [1.9, 0.1], L_c = 8, batch 64, 40k steps, lr 5e-4, 10% warmup + cosine, grad clip 1.0. LoRA rank 32 on LLM / vision encoder / action head / proprio projector; AVA modules fully trained. Initialized from official OpenVLA-OFT checkpoints.
  • Inference: fully recurrent, r_(-1) = 0̄ at episode start; each pass emits the action chunk and the new recurrent state.
You cannot shuffle inside a window, and one "batch" is now 4 sequential forward passes. That is the price of leaving the Markov world.

🖊 Questions I had

It only uses the previous step — so is it really "history"?

Half right. Formally it chains like an RNN:

r_0  <- from a pass that saw x_0
r_1  <- from a pass that saw x_1 AND r_0
r_2  <- from a pass that saw x_2 AND r_1     so r_2 contains traces of x_0

Same trick as an LSTM hidden state — you read one vector, but it was cooked from all the vectors before it. In principle the whole episode is compressed in there.

In practice the memory is short. Training samples windows of T = 4, and the gradient is detached between step 2 and step 3, so gradients flow across only 2 steps. The model is never explicitly rewarded for remembering something 20 steps back. Any long memory is a side effect, not something the loss trains. There is also no gate/forget mechanism — just an MLP squeezing hidden states each step, so old information washes out fast.

So: the architecture allows long history, the training teaches about 2 steps of it.

So the action slots are not zero in the following steps?

Correct.

t = 0   slots = 0        <- zeros, only here
t = 1   slots = r_0
t = 2   slots = r_1
t = 3   slots = r_2

Three consequences:

  1. At t=0, AVA-VLA is just plain OFT. Zeros in the slots, and the gate ω is computed by cross-attending to a zero memory, so it carries no signal either. The first decision of every episode is history-free — unavoidable, there is no history yet.
  2. The slots became a warm start. In OFT the model built the chunk from nothing, using only position to tell slot 3 from slot 40. Now slot 3 arrives already holding "what I was thinking about action dim 3 last step". Consecutive chunks in smooth manipulation are similar, so that is a good initial guess — the model refines instead of building from scratch.
  3. Reset on episode boundary, or memory from grabbing a cup leaks into a drawer task.
But the next step already gets a fresh image — isn't the update already there?

The new image gives an update, but a different kind.

new image tells you:   WHERE things are now
new image does NOT:    WHAT you were trying to do
                       WHAT you already finished
                       WHERE you were looking

The camera reports geometry, not intent.

Concrete case — LIBERO-Long, "put the bowl in the drawer, then close the drawer":

moment A:  arm near the drawer, gripper empty, drawer open  -> correct: reach for the bowl
moment B:  arm near the drawer, gripper empty, drawer open  -> correct: push the drawer closed

The two images are basically identical. A Markov policy must pick one, so it outputs something in between or is wrong about half the time. With r_(t-1) the model carries "I already placed the bowl" forward: same image, different memory, different action.

The second thing is gaze stability — the "active" part. Without memory the model re-decides where to look from scratch every 0.27 s, and its focus jitters. The paper's own failure example is exactly this: plain OFT loses the stove switch. With r_(t-1) driving the gate, attention becomes sticky.

Their numbers support the objection, partly. On short fully-visible tasks the observation really is enough:

LIBERO-Spatial (short, everything visible):  97.7 -> 97.4     slightly WORSE
LIBERO-Long    (long, multi-stage):          95.3 -> 97.6     +2.3
CALVIN chain length 1:                       96.3 -> 99.6     +3.3
CALVIN chain length 5:                       66.5 -> 84.1     +17.6

The benefit only appears once the task is long enough that the image alone becomes ambiguous.

🖊 Fair criticisms

  • The "recurrent state" is one MLP on last-step hidden states. Calling it a belief state is generous.
  • Gradients cross only 2 steps, so the learned memory is short. No forget/gate mechanism.
  • No latency or throughput numbers reported. The AVA module runs cross-attention every step and modifies attention in all 32 layers — OFT's whole selling point was speed, so this omission is notable.
  • No seeds or variance on the benchmark tables. A +1.2 gain at 97% saturation could partly be noise.
