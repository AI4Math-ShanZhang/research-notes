VPP2 on RoboDojo — the data, the benchmark, and how real-robot eval works

Papers: Video Prediction Policy 2: Predict Better, Act Better — Guo, Yan, Zhong, Zhang, Yang et al. (RobotEra · Tsinghua · HKUST-GZ · UC Berkeley · SJTU), Oct 2026, arXiv:2610.10270 · code; and RoboDojo: A Unified Sim-and-Real Benchmark for Comprehensive Evaluation of Generalist Robot Manipulation Policies — Chen, Chen, Li et al. (HKU MMLab + ~20 institutions), Jul 2026, arXiv:2607.04434 · website · data. This note covers what VPP2 trains on, what RoboDojo actually tests, and the practical questions on running a VLA on RoboDojo's real robots.

📄 Paper Summary

VPP2 in one line

Stage 1: Wan2.1-I2V-14B  →  predict a WHOLE sub-task event (49 frames, detailed caption)
Stage 2: predict a FIXED future window (8 s robot / 2 s hand), distill to 1-step (~0.12 s)
Stage 3: add a 0.9B action DiT (MoT), reads the video latents → 2 s action chunk (~0.1 s)
Test:    VLM splits the task into sub-tasks → VPP2 runs each one         total ≈ 0.22 s / chunk

More than 20 robot types in total. Two-arm, first-person data (ALOHA-style, humanoid, human) is more than 80%. The paper does not give total hours or clip counts.

How each clip is processed

  1. Clean — drop broken videos (camera failure, jumps).
  2. Cut into events of 1–12 s, one sub-task each. Cut points: hand/gripper slows down, or gripper opens/closes. A VLM then merges or fixes the cuts.
  3. Detailed caption by template: how the task is done; which hand/gripper moves (must be visible in frame 1); which object, without ambiguity ("the leftmost yellow box"); camera view and motion (too much shake → removed by optical flow).
  4. T-shape image — main view on the left, two extra views stacked on the right, black if missing.
  5. One action space — every robot is mapped to a shared world frame and a shared gripper frame, so "move left" means the same numbers in every dataset.
Why detailed caption + whole event: "place the bowl" + a short future clip matches many different futures, so the model learns weak short-range shortcuts. A detailed caption + the full event gives almost one clear future per instruction.

Results

  • Video instruction-following: VPP2-14B 0.80 / 0.90 (human / robot) vs Cosmos3-64B 0.70 / 0.78.
  • Zero-shot real ALOHA, 10 task types: 58.5% vs π0.5 40.0% vs Fast-WAM 20.5%.
  • LIBERO-Pro 45.0% (best baseline 11.0%), LIBERO-OOD 63.9%.
  • RoboDojo simulation: 32.26% success / 39.26 score, top of the leaderboard at the time.

🖊 My Key Notes

RoboDojo is not a sim-to-real transfer test. The paper says it directly: "we do not construct one-to-one aligned task pairs between simulation and the real world." Sim policies train on sim data, real policies train on real data. VPP2 reports only the sim part.

Q&A — the benchmark

What does each simulation dimension test, and what are the tasks?
DimensionWhat it testsTasks
Generalization (12)New backgrounds, lighting, up to 25 clutter objects, new targets. 25 standard + 25 random episodes. stack_blocks, arrange_largest_number, hang_mugs, pack_objects_into_box, make_toast, pour_liquid_into_cup, push_T, sort_nesting_dolls_by_size, fold_clothes, stack_bowls, store_laptop_and_headphones, sweep_blocks
Memory (6)The right action depends on something seen earlier. cover_blocks, imitate_sorting_sequence, swap_T, press_by_number, match_and_pick_from_conveyor, swap_blocks
Precision (8)Exact placement, contact-rich control. build_tower, deposit_coin, fasten_screws, insert_key, insert_tubes, play_Xylophone, plug_in_charger, pour_balls_into_vase
Long-Horizon (8)Many steps in a row, sometimes a hand-over between arms. classify_objects, fill_egg_holder, fill_pen_holder, put_bottles_into_dustbin, make_kong, organize_table, play_stacking_toy, play_tic_tac_toe
Open (8)No training data. Reuse learned skills for new language goals. align_blocks, classify_objects_by_language, general_pickup, store_tools_into_toolbox, pick_from_conveyor_by_image, solve_equation, stack_blocks_by_language, pour_by_language

Success rate = full task done. Score = also gives credit for finished steps. The final number is the mean over the 5 dimensions, not over tasks, so Generalization (12 tasks) does not dominate.

How did VPP2 do per dimension?
success %   Gen std 46.4 | Gen rand 12.6 | Precision 35.2 | Long-Horizon 37.0 | Memory 55.6 | Open 4.1
avg = (mean(46.4, 12.6) + 35.2 + 37.0 + 55.6 + 4.1) / 5  ≈  32.3

Strong on memory (they add frame 0 + 8 past frames, one per second), but Open is only 4% — the dimension with no training data. GPT-6-Astra gets 31% there. Adding a VLM sub-task planner on 5 task groups raises them from 27.6% to 57.6% (tic-tac-toe 0% → 38%).

Do sim and real rankings agree?

Only partly. π0.5 is best in real (12.8%) and also strong in sim, but some policies drop a lot on real robots. Real adds sensor noise, calibration error, actuation delay, contact instability and drift — things sim does not fully model.

Same station for all: one Gemini 335L head camera + two Gemini 305 wrist cameras (640×480), a 1.2 m × 1.2 m table, fixed LED light and curtains, 3D-printed mounts. A start-layout image is overlaid on the live camera so staff can reset the scene the same way every trial.

To evaluate on these robots, do I need to collect my own data on them?

No. The real training data is public (Apache-2.0, no gate) on Hugging Face:

data/RoboDojo_real/<task>/<robot>/data/episode_0000000.hdf5 ... episode_0000099.hdf5
   → 100 demos per task × 18 tasks = 1,800 demos
   → each ≈ 80 MB  →  ≈ 8 GB per task  →  ≈ 140–150 GB for all real data (my estimate)

Each demo: joint states, end-effector pose, language instruction, 3 camera videos. Collected with leader-follower teleop where the leader arm is the same robot type, so actions are in the robot's own joint space. The same repo has the sim data (raw + LeRobot v2.1 / v3.0, joint and end-effector) and baseline checkpoints.

Do I run my VLA as a server, or send them my checkpoint?

Both are allowed (paper App. A.2: "submitting a deployable policy package or by connecting a remote policy server").

Your GPU (your lab)                         RoboDojo lab
 VLA = policy SERVER   ←── 3 images + robot state ───   real robot = environment CLIENT
                       ─── action chunk ──────────→     executes, asks again
              WebSocket + MessagePack (XPolicyLab protocol)
  • A. Your server: weights never leave your machine — good for private testing. Watch the network delay: the paper's own timing used a GPU on the same local network as the robot. Over the internet, use larger action chunks.
  • B. Policy package: they run it on their GPU next to the robot — no delay, but you hand over the model.

Official verified leaderboard needs more: all 3 robots, a hidden-layout check, and at publication time you must release checkpoint + code + config through XPolicyLab. Otherwise the result goes to a separate, unofficial closed-source track. Test the server in sim first — sim uses the same client-server protocol.

Q&A — VPP2's data

Is VPP2's "general video" robot data, or just for entertainment-style generation?

Neither. It is web video (OpenVid, Panda-70M, made for text-to-video) filtered to keep only human hands manipulating objects. Table 1 lists its embodiment as "Human hands". It is the same kind of content as Ego4D / EgoDex, but from random, often third-person web clips.

StageUses general video?
1 — event-level video pretrainingYes — more varied hand-object scenes for prediction
2 — fixed window + distillationProbably (not stated clearly)
3 — action modelNo — no robot actions; only aligned two-arm robot data

It only teaches the model to predict the future picture; actions are read off that prediction later. The paper gives no size and only says the filter is "similar to LVP" (arXiv:2512.15840).
