InternW0-Δ — Causal Imprint and the Data Behind It

Paper: InternW0-∆: A World Action Model Bridging Predictive Dynamics and Actions with 20K+ Hours of Open Data — Physical Intelligence Team, Shanghai AI Laboratory, Sep 2026, arXiv:2609.31394 · project page · code. This note covers the model step by step, then the data questions I had to work out: what UMI, teleoperation and Ego2Robot data actually are, and what the Δz target really is.

📄 Paper Summary

The idea in one line

action chunk = ActionExpert( what you see now  +  Δ tokens  +  VLM scene features )

Δ is trained to predict how the future video will change — but no future video is made at test time.

Step by step

  1. One format for every robot. All datasets are mapped into one 80-slot vector (arm joints, end-effector, gripper, hand, ×2 arms; plus torso, head, base). Unused slots are masked.
  2. 23,072 hours of data.
    SourceHoursShare of samplesAction-loss weight
    Robot (15 datasets, mostly teleop)11,30280%1.0
    Ego2Robot5,634*10%0.1
    Ego (raw human video)4,0612%0.1
    UMI2,0758%0.5
    * only 1,101 real hours of human video converted; the number grows because each clip is counted once per robot type and slowed down 2×.
  3. Inputs. Video expert sees A, R, C latents + T5 text. Action expert sees VLM features + state. They are joined in 30 shared Mixture-of-Transformers blocks (own weights, one shared attention).
  4. Attention mask — the key trick. 
    F   sees {A, R, C, F}          → learns to predict the future
Δ   sees {R, C, Δ}             → cannot see F
Act sees {A, R, C, Δ, Act}     → cannot see F
    The future is only a training target; nothing leaks into the action path.
  5. Two losses on Δ.
    • L_Δ: final-layer Δ must output the clean latent changes Δz.
    • L_align: Δ features at block 8 must match (cosine) the video expert's features of the last future frame at block 20 (stop-gradient).
  6. 4D distillation (training only). Frozen Track4World gives a 1430-d clip descriptor (geometry 1024, 2D motion 128, 3D motion 256, camera 18, visibility 4); a 16-query decoder on layer 15 must match it with MSE. Only the last 10K of 245K steps, on 1 of 16 samples.
  7. Total loss. 0.5·video + action + 0.5·L_Δ + 0.1·L_align + 0.1·L_4D, on 256 A800s, batch 4,096.
  8. Inference. Run the video expert once over A, R, C, Δ (no F) and cache K/V; then N flow steps on the action expert only. 152.8 ms round trip on one RTX 5090 (780.5 ms before, 5.11×), LIBERO-Plus 92.78 → 92.23.

🖊 My Key Notes

At test time this is a VLA with a video-pretrained backbone. The "world model" shapes the features in training, then the future branch is switched off — the same bet as Fast-WAM.

Q&A — the data types

What is UMI data?

UMI = Universal Manipulation Interface (Chi et al., 2024). A person holds a 3D-printed tool shaped like a robot's two-finger gripper, with a GoPro on it looking at the fingers, and does the task by hand. Each frame gives: wrist camera image, gripper 3D position + rotation, gripper width, text. The robot later carries the same gripper and camera, so the images look like what the robot sees and the action is already in robot form (end-effector pose + width). The paper uses Hy-UMI-10K (2,162 h, adds a head camera).

How is that different from teleoperation?

In teleoperation a real robot moves: a person drives it with VR, a joystick or a leader arm, and the robot records its own joints and cameras exactly. In UMI there is no robot: the person pretends to be the robot by holding its "hand".

If I hold the tool, isn't it the gripper? Why must its position be estimated?

The tool is plastic + a camera — no motors, no sensors. A robot knows its gripper position because every joint measures its angle and the base is bolted down; then simple math gives the position:

part 1: 0.5 m, angle 0°  (flat)
part 2: 0.3 m, angle 90° (up)
gripper = (0.5, 0) + (0, 0.3) = (0.5, 0.3) m      ← measured, exact, every tick

The handheld tool floats in a human hand that has no sensors. So UMI uses SLAM: the camera sees the room move ("table edge moved 2 cm left → I moved 2 cm right") plus the motion sensor (IMU) for fast moves. Finger width comes from markers on the fingers seen by the camera. SLAM can fail (fast shaking, plain walls), which is why the paper drops UMI segments with broken quaternions, both-hands-static segments, and sudden jumps.

What is Ego2Robot?

Turn a human first-person video into a fake robot video. Source: EgoDex (772 h, Apple Vision Pro) and EgoVerse (3,289 h), which come with tracked 3D hand joints.

  1. Action alignment — wrist → end-effector; finger pinch → gripper opening: d = thumb tip to midpoint of index & middle tips; 5 cm → 0 (closed), 7 cm → 1 (open), 6 cm → 0.5. Slowed 2×.
  2. Kinematic alignment — put a virtual robot in MuJoCo and solve inverse kinematics (position → joint angles, the reverse of the example above). If it can't follow (reach, joint limits, jumps, arm collision), move the base and retry; if nothing works, drop the clip.
  3. Visual alignment — SAM3 finds the human, ProPainter erases it, the robot is rendered from the same camera and pasted in with depth so objects in front still cover it.

Only 27% of human video converts (4,061 → 1,101 h). It helps more than raw ego (+2.3 vs +0.3 on RoboTwin) but far less than real teleop (+28): the motion is still a human motion, and the rendered robot never touched anything.

The pattern: the closer the data looks and acts like a robot, the more it helps — teleop (+28) > UMI (+11.1) > Ego2Robot (+2.3) > raw ego (+0.3). Raw human video is still an open gap; the authors say so in their limitations.

Q&A — what Δz really is

Is z the visual tokens, not the robot state?

Yes. z is the VAE-compressed camera image — a grid, one cell per patch. Δz is the change per cell: "how did this patch of the picture change?" Toy 3×3 grid, gripper (5) moving to a cup (3):

z_t            z_t+1          z_t+2
0  0  0        0  0  0        0  0  0
5  0  3        0  5  3        0  0  8      (8 = gripper on cup)
0  0  0        0  0  0        0  0  0

Δz_1 = z_t+1 − z_t     Δz_2 = z_t+2 − z_t+1
 0  0  0                0  0  0
-5 +5  0                0 -5 +5
 0  0  0                0  0  0

Zero almost everywhere except where things move — that's why it's called "change-oriented". There is one Δ token per cell, each guessing how its own patch will change. The robot arm is in the picture, so Δz covers robot and object motion, but as appearance change, not as "joint 3 rotated 10°". The action expert turns "what will change where" into joint and gripper numbers.
