AW-0 Agentic World Action Models — code expert, annotation pipeline, memory and hybrid actions

Paper: Agentic World Action Models — Zhuoyang Liu, Dantong Niu, Botong Zhang, Boning Shao, et al. (UC Berkeley, NVIDIA, UPenn; advised by Yuke Zhu, Guanzhi Wang, Jim Fan, Trevor Darrell), Oct 2026, arXiv:2610.30136 · project page. This note covers what the code expert outputs and how it guides video and action, the agentic annotation pipeline, the memory cache, hybrid (Code-as-Policies) execution, and how training differs from the 4-step inference.

📄 Paper Summary

Idea

A World Action Model (WAM) predicts future video and robot actions together, but has no explicit way to plan or reuse skills. AW-0 adds a code expert: one model jointly generates three streams — a short skill program (code), future video, and an action chunk.

Architecture (Mixture-of-Transformers, 28 layers each, shared attention)

ExpertInitGeneratesHow
CodeSDAR-1.7B (frozen FFN/embeddings) + frozen Qwen3-VL ViT128-token Python sliceLLaDA-style masked diffusion
VideoCosmos-Predict2.5-2B, Wan2.2 VAE9 future frames × 3 viewsflow matching
ActionDiT from scratch32 steps × 64-D (both arms: EEF pose + 22 hand joints + gripper)flow matching

Attention is bidirectional inside each expert and blockwise causal across experts in the order Code → Video → Action.

Data

Pretrain on ~2,000 h YAM robot data + ~1,000 h egocentric human video, all labeled with code by an agentic pipeline (Gemini 3.1 Pro annotator + Claude Code coordinator) that also discovers a library of 50 reusable skills. Fine-tune with 100 demos per real task, 50 per RoboTwin task.

🖊 My Key Notes

Q&A — the code expert

What does the code expert output? Is it executable? How does it affect the video and action experts at inference?

Output: a short Python "slice" — a few API / skill calls plus comments for the next subtask only. A real online output (Pack Backpack, matched the annotation exactly):

# STAGE 2/5 -- OPENING, right arm: grasp the pull at the MIDDLE of the seam.
# Lift UP, then slide MIDDLE -> RIGHT; after this the backpack is fully OPEN.
approach_best_grasp(robot, 'zipper pull', 'right', [0.0, 0.0, 0.05])
robot.close_gripper('right')

Executable? It is valid Python (87.5% parse rate) and can run, but by default it is not run: "it serves as a subtask plan that conditions the action expert", and the action chunk drives the robot.

Effect: through attention during joint denoising. Video attends to code; action attends to code + video. All three are denoised together in 4 steps; code reveals 128 / 4 = 32 tokens per step, so video and action read a plan that gets clearer each step.

VariantReal avgLatency
No code (V → A)32.9%0.19 s
Code, autoregressive54.5%0.55 s
Code, joint denoising (C → V → A)71.1%0.23 s

V → C → A is worse than C → V → A: the code must guide the video, not just read it.

If the code is not run, how is it different from a natural-language instruction?

When not run, it is a structured language plan — the gain comes from what it contains, not from executability.

Q&A — the annotation pipeline (Fig. 3)

What are "predefined declaration-only APIs" and the Claude Code coordinator? How does the pipeline work?

Declaration-only = names and arguments exist, bodies are empty:

class ParallelGripperApi:
    def pick(self, object_name, side): ...
    def grasp(self, object_name, side): ...
    def place(self, object_name, target_name, side): ...
    def servo_ee_delta(self, side, delta_pos, duration_s=1.0): ...
    def detect_objects_oneshot(self, query, camera='top'): ...

The programs are labels, not controllers: never run, only checked statically (syntax, function exists, arguments bind, literals in vocabulary). On failure the annotator sees the errors and rewrites.

Q&A — memory cache

What memory do they use? "History slices compressed into K learnable memory slots, read back as prefix tokens" — what is the pipeline?

One image often cannot show progress (a folded towel looks the same before and after stacking), so the code expert gets the code it already wrote this episode.

episode start:  buffer = []
replan 1:  [visual | instruction | 128 MASK]                   → slice_1   buffer=[s1]
replan 2:  [s1]  ──compress──▶ K slots
           [K memory slots | visual | instruction | 128 MASK]  → slice_2   buffer=[s1,s2]
replan 3:  [s1,s2] ──compress──▶ same K slots ...
  • Stores past code slices only (not images or actions); fixed K vectors however long the episode.
  • Only the code stream reads it; video and action get it indirectly through attention to code.
  • Progress also lives in the code comments: # STAGE 3/6 FOLD BROWN | folded: pink, green | stack: empty.
Not given in the paper: K, p, the compressor design, or a memory ablation. A Perceiver / Q-Former-style cross-attention is my guess, not stated.
"During training the buffer holds annotated slices, replaced with probability p by the model's own predictions" — what does that mean?

Training normally fills memory with correct labels, but at test time memory holds the model's own (maybe wrong) code. If it only ever saw correct memory, one wrong slice at test time would snowball.

correct memory:   s1 "STAGE 1 fold pink"  ✔   s2 "STAGE 2 fold green" ✔
test-time memory: s1 "STAGE 1 fold pink"  ✔   s2 "STAGE 2 fold brown" ✘

training: for each history slice, flip a coin (e.g. p = 0.3, my example)
   70% → ground-truth slice     30% → model's own prediction
target for the next slice stays the CORRECT one

So the model learns to write the right next step from the current image even when memory has small errors. Same idea as scheduled sampling (vs teacher forcing) in sequence models.

Q&A — hybrid actions

What is hybrid (Code-as-Policies) execution? Example?

One forward pass gives both an action chunk and a code slice; an arbiter picks one at each replan:

loop:
  actions[1..32], code = model(obs, instruction)
  if code passes all gates:  run code     # chunk discarded, even if code raises
  else:                      play actions[1..32]

gates (no repair):  1 stage gate   — stage not done, not earlier, < R failures
                    2 dependency   — every variable it reads exists in namespace G
                    3 syntax / whitelist / vacuity — compiles, only allowed calls, has a real statement
                    + skip a retry if it already failed and nothing changed
# generated towel-stacking slice (Fig.): code handles the structured stacking
for towel, arm, target_pos in [('pink towel','right',[0.44,-0.08,0.77]),
                               ('brown towel','left',[0.47,-0.04,0.81]),
                               ('green towel','right',[0.42,-0.09,0.79])]:
    approach_best_grasp(robot, towel, arm, [0.0, 0.0, -0.05])
    robot.grasp(towel, arm)
    robot.servo_ee_delta(arm, [0.0, 0.0, 0.08])     # lift clear
    robot.freespace_move(...target_pos...)
    robot.servo_ee_delta(arm, [0.0, 0.0, -0.07])    # lower onto pile
    robot.release(arm)
  • Towels: soft folding → action expert; approach + stacking → code (gets the order right).
  • blocks ranking rgb: pick-and-place almost all code. pick dual bottles: code finds the bottle but fails the grasp → action expert finishes → code resumes.

The APIs are declaration-only — so how can hybrid code actually run?

There are two versions of the same API: same names and arguments, but for hybrid the bodies are real.

  • No privileged simulator state at test time — camera images only.
  • Real-robot hybrid only on YAM: no CaP library exists for the dexterous hands.
  • Sim hybrid was trained on separate CaP-collected demos (programs by Claude Opus 4.8), so the paper admits the comparison "does not isolate the effect of hybrid execution alone".

Q&A — training vs 4-step inference

The code expert unmasks over 4 steps — does training also do 4 forwards? How do video and action denoise alongside the code unmasking?

No — training is one forward pass per sample. Each stream gets an independent random corruption:

StreamCorruptionRandom level
Codeeach token → [MASK] w.p. rr ~ U(0,1)
Video(1−σ)·clean + σ·noise50% Cosmos schedule (high noise) + 50% uniform
Action(1−σ)·clean + σ·noiseuniform, shifted to high noise (shift 5)

One pass → code CE on masked positions + video and action flow-matching (target = noise − clean). Loss weights video 1, code 0.5, action 1.

sample 1: code 90% masked | video σ=0.2  | action σ=0.7
sample 2: code 10% masked | video σ=0.95 | action σ=0.3
sample 3: code 50% masked | video σ=0.6  | action σ=0.9
→ the model sees every mix, so at inference any intermediate state is familiar

Inference: 4 forward passes. Each pass gives code logits + video velocity + action velocity:

              code canvas         video σ     action σ
start           0/128 revealed    1.0         1.0
step 1  →      32/128             ↓           ↓      code: keep top-32 confident, revealed stay fixed
step 2  →      64/128             ↓           ↓      video: one UniPC step
step 3  →      96/128             ↓           ↓      action: Euler  A ← A + (σ_next − σ_now)·v
step 4  →     128/128             0           0      → play the 32-step chunk
Code attends only to itself (+ image, instruction, memory), never to video or action. So the code result does not depend on them — you could decode it alone first and get the same code. "Joint" mainly buys speed (4 passes total; 0.23 s vs 0.55 s for AR) and avoids AR's teacher-forcing error build-up (71.1% vs 54.5%), while video and action read the code as it forms.
