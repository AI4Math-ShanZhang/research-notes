SMWM — Feature Collapse and Low-Dimensional Latents

Paper: Sensorimotor World Models: Perception for Action via Inverse Dynamics — Petr Ivashkov, Randall Balestriero & Bernhard Schölkopf (MPI-IS Tübingen · Brown · ELLIS · ETH), June 2026, arXiv:2606.20104. Read together with MotionJEPA (arXiv:2609.23881), which uses SMWM as a baseline. This note focuses on two questions: what "collapse" means and why it happens, and whether the encoder's embedding must be low-dimensional.

📄 Paper Summary

Notation

SymbolMeaning
o_timage at time t
a_taction taken between o_t and o_(t+1)
f (encoder)z_t = f(o_t)
g (forward model)ẑ_(t+1) = g(z_t, a_t) — guess the next latent
h (inverse model)â_t = h(z_t, z_(t+1)) — guess the action from two latents
λweight of the inverse loss (the only new hyperparameter)

The method in one line

L = || ẑ_(t+1) − z_(t+1) ||²   +   λ · || â_t − a_t ||²
       forward loss                   inverse loss (anti-collapse)

Both losses send gradients into the encoder. There is no SIGReg, no EMA target, no frozen encoder. The only thing added to LeWM's architecture is a 2-layer MLP (width 256) for h.

Why the inverse loss blocks collapse. If every z were the same, h would always get the same input and could only output the average action. Example: actions Δx uniform in [−1, 1] → average 0 → best collapsed error ≈ 0.33. To beat that, (z_t, z_(t+1)) must contain real information about the move.

🖊 My Key Notes

Q1. What is "feature collapse", and why does it happen?

Collapse = the encoder stops putting useful information into z. There are three levels:

LevelWhat happensExample
Full collapseevery image gives the same z ball-left and ball-right both → [0.3, 0.3, …]; SMWM's Forward-only (Fig. 11)
Dimensional collapsez varies along only a few directions not always bad: 2 directions for a 2-D dot is correct
Feature collapsesome features kept, others dropped MotionJEPA, Pong, LeWM: score kept (probe error 0.003), ball lost (0.999), bats lost (1.002)

Feature collapse is the hardest one to see: z is not constant, so the training loss looks fine. You only find it by probing.

Why it happens: the forward loss rewards "easy to predict", not "informative". The encoder makes both the prediction and the target, so it can make the task easier by encoding less.

What the encoder keeps in z (Pong)How hard is next z to predict?Forward loss (illustrative)
ball + bats + scoreball bounces — hard0.20
score onlyalmost never changes — easy0.01
nothing (constant)trivial0.00

Gradient descent goes downhill, so it throws away the fast, hard features first (ball, cactus, obstacles) and keeps the slow, easy ones (score, sky, background). MotionJEPA shows this directly: an untrained random encoder still holds the ball (error 0.143), and training makes it worse.

How each method pushes back — each adds a term that gets worse when information is missing:

MethodExtra termForces z to keepCan still lose
Forward-onlynonenothingeverything
LeWMSIGReg: z looks like a spread-out Gaussiansome spread, of any kindfast features (it can use score/sky for spread)
SMWMguess the action from (z_t, z_(t+1))what the agent controlsuncontrolled movers (Pong ball: 1.001, Golf obstacles)
MotionJEPAguess DiffEnc(o_(t+1) − o_t) + SIGRegeverything that moves + static thingsleast in their tests
MotionJEPA is SMWM with one change: the inverse head's target is the embedding of the frame difference instead of the action. The action only covers what the agent controls. The frame difference covers everything that moved.
Q2. Does Fig. 6 mean the encoder's embedding should be low-dimensional?

Not exactly. The encoder output is still 192 numbers, and nothing is made smaller. The points just use only a few directions inside those 192.

  • Ambient dimension = how many numbers z has → always 192.
  • Effective (intrinsic) dimension = how many directions the points actually spread along → about 2 for TwoRoom, about 4 for Reacher.
3-d toy example:
  z = (1.0,  2.0, 0.01)
      (3.0, −1.0, 0.00)
      (−2.0, 0.5, 0.02)
  3rd number is always ≈ 0  →  all points lie on a flat sheet
  PCA: 2 tall bars, 1 bar ≈ 0  →  ambient 3, effective 2

Is it forced? No. No loss term asks for low dimension. It happens by itself: the inverse loss keeps what the action needs, the forward loss drops what is hard to predict (like random distractors), and the remaining directions are unused, so their variance is about 0.

Is it required for a good world model? No — it is nice to have:

  • Good: easy to read (x–y in PC1/PC2, the torus in Reacher).
  • SIGReg spreads variance over all 192 directions (flat spectrum) and still plans about as well on the 2D tasks (94/67/83 vs 99/66/87). It only clearly loses on Cube (59 vs 84).
  • Risk: "only what I control" also drops uncontrolled things you may need (the Pong ball).
Low effective dimension here means "only the dimensions that matter for control". That is good if the task only needs controlled things, and bad if you also need moving objects you do not control.
Weak points
  • It assumes the action is visible between two frames; if two actions give the same image change, h cannot tell them apart.
  • Single-frame encoder → no velocity in z.
  • Small-scale evidence: toy dots plus four simulated tasks. Push-T block orientation is weaker than SIGReg (linear probe 0.664 vs 0.931).
  • Inverse dynamics itself is not new (Pathak's curiosity work 2017, PLDM); the new part is using it as the only anti-collapse term.
Summary. SMWM stops JEPA collapse with one extra head that guesses the action from two consecutive latents, so z keeps what the agent controls and drops the rest. Collapse happens because the encoder makes its own prediction target, so encoding less lowers the forward loss, and fast things are dropped first. SMWM's embedding is still 192-d, but it lives on a small subspace; this is not forced and not required, just a readable side effect.
