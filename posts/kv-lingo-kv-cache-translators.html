KV-Lingo — Translating One Model's KV Cache into Another's

Paper: KV-Lingo: Learning KV-Cache Translators with Distillation — Valérie Castin, Keitaro Sakamoto, Anastasiia Filippova, João Monteiro, Marco Cuturi & Pierre Ablin, arXiv:2609.32610.

📄 Paper Summary

Different language models write different KV caches. So when you switch from one model to another in the middle of a shared context, the new model normally has to read the whole context again (re-prefill). KV-Lingo learns a set of linear maps, usually one per layer of the target model, that turn the source model's KV cache into the target model's format. The maps are trained by distillation: the target model's next-word predictions from the translated cache should match its predictions from its own real cache.

  • 9.6× faster time-to-first-token after a model switch on 64-token prompts (Qwen models, Apple M3 Ultra).
  • Up to 29× faster at 32k context on an H100.
  • Downstream quality stays strong in both directions, small → large and large → small.
  • The translators are trained on a generic text corpus, and they make it possible to route between models without re-prefilling the shared prefix.

🖊 My Key Notes — the flow, step by step

This walkthrough uses the paper's own example from Figure 1: a document about the James Webb telescope, then the question "Where is the JWST located?".

Step 1: the small model S reads the document (once)

 document tokens:   "The"  "JWST"  "was"  "launched"  ...  "Where" "is" "JWST" "located" "?"
                      │      │       │        │                │      │     │       │
                      ▼      ▼       ▼        ▼                ▼      ▼     ▼       ▼
 ┌─────────────────────────── SMALL MODEL S  (prefill) ───────────────────────────────┐
 │  layer 1  ──► writes K¹,V¹ for every token                                         │
 │  layer 2  ──► writes K²,V² for every token                                         │
 │    ...                                                                             │
 │  layer N  ──► writes Kᴺ,Vᴺ for every token                                         │
 └────────────────────────────────────────────────────────────────────────────────────┘
                      │
                      ▼
          S's KV cache  =  a table of notes:

                 token1  token2  token3  ...  token n
          layer1 [K,V]   [K,V]   [K,V]   ...  [K,V]
          layer2 [K,V]   [K,V]   [K,V]   ...  [K,V]
           ...
          layerN [K,V]   [K,V]   [K,V]   ...  [K,V]

          (written in S's "private language")

Step 2: the translator converts the notes (this is KV-Lingo)

          S's cache                    TRANSLATOR                 L's-format cache
                                  (only trained part,
                                   frozen models around it)

  layer 1  K¹,V¹  ──────►  K̂ = T_K¹ · K     V̂ = T_V¹ · V  ──────►  layer 1  K̂¹,V̂¹
  layer 2  K²,V²  ──────►  K̂ = T_K² · K     V̂ = T_V² · V  ──────►  layer 2  K̂²,V̂²
   ...                          ...                                  ...
  layer N  Kᴺ,Vᴺ  ──────►  K̂ = T_Kᴺ · K     V̂ = T_Vᴺ · V  ──────►  layer M  K̂ᴹ,V̂ᴹ
  • One key matrix and one value matrix per layer of L.
  • Applied to each token separately (token 1, token 2, … one by one).
  • If L has more layers than S, each L layer reads a few nearby S layers.
No text is involved here. It is just numbers → matrix multiply → numbers.

Step 3: the big model L uses the translated notes and answers

 ┌──────────────────────────── BIG MODEL L ────────────────────────────┐
 │                                                                     │
 │   translated cache (K̂,V̂) for tokens 1 … n-1   ◄── from Step 2      │
 │                    ▲                                                │
 │                    │ attention (looks up the notes)                 │
 │                    │                                                │
 │   last token "?" ──┴──► ONE forward pass through L's layers         │
 │                                 │                                   │
 │                                 ▼                                   │
 │                     first answer word: "The"                        │
 │                                 │                                   │
 │                                 ▼                                   │
 │          keeps generating normally: "JWST is located at L2 ..."     │
 │          (each new word adds L's own real K,V to the cache)         │
 └─────────────────────────────────────────────────────────────────────┘
L never reads "The JWST was launched ..." itself. It only reads the notes S made, translated into its own format.

The whole picture

                    reads text                 translate              answers
 document ──► [ SMALL MODEL S ] ──► S-cache ──► [ T ] ──► L-cache ──► [ BIG MODEL L ] ──► answer
                (slow part,                  (cheap,                (1 step, then
                 done once)                  linear)                 normal generation)

 WITHOUT KV-Lingo:
 document ──► [ SMALL MODEL S ] ──► S-cache        (thrown away)
 document ──► [ BIG MODEL L ] ──► L-cache ──► answer           ← L re-reads everything (slow)

How the translator T is trained

 same text ──► S ──► S-cache ──► T ──► translated cache ──► L ──► next-word probs  P₁
 same text ──► L ──────────────────► L's real cache ──────► L ──► next-word probs  P₂

 Stage 1:  make translated cache ≈ real cache          (least squares, closed form)
 Stage 2:  make P₁ ≈ P₂   (minimise KL)                 ← the stage that really matters
           only T changes; S and L stay frozen

Summary

The small model reads the document once and leaves a table of K/V notes, one entry per layer per token. KV-Lingo runs every note through a per-layer matrix to rewrite it in the big model's format. The big model then puts those notes straight into its cache and starts answering with a single step, without ever reading the document itself.
