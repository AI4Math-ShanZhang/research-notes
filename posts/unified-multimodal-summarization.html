Unified Multimodal Understanding and Generation — Architecture Summarization

Paper: Unified Multimodal Understanding and Generation Models: Advances, Challenges, and Opportunities · arXiv:2505.02567. Notes on Figure 5 — the architecture taxonomy, and how the conditioning works.

Figure 5 is best read as a taxonomy of alternative designs—not a strict chronological sequence of upgrades. Each architecture makes a different trade-off between:

  • understanding what an image means;
  • preserving exactly what the image looks like;
  • generating language efficiently;
  • generating globally coherent, high-resolution images.

The central conflict

Text and images have very different structures:

TextImage
Discrete tokensContinuous, dense spatial signal
Naturally sequentialStrong 2-D global dependencies
Meaning is most importantBoth meaning and pixel detail matter
Well suited to next-token AR predictionWell suited to parallel denoising

A second conflict is between image understanding and image reconstruction:

  • A semantic encoder such as CLIP/SigLIP learns that two visually different images can mean the same thing. This invariance helps reasoning.
  • A pixel encoder such as VAE/VQGAN must preserve color, position, texture, and shape so that the image can be reconstructed.

In other words:

Understanding wants to discard irrelevant pixel details, while generation needs many of those details back.

Most of Figure 5 is showing different solutions to this conflict.

What each block does

The components in the figure have distinct responsibilities:

  • Text tokenizer: converts text into discrete language tokens.
  • Pixel encoder: compresses an image into reconstructable visual codes.
  • Semantic encoder: converts an image into language-aligned concepts.
  • Learnable queries: select a small, task-relevant subset of visual information.
  • MLLM/AR backbone: reasons and predicts sequentially.
  • Diffusion component: generates or refines many image latents together.
  • Pixel decoder: reconstructs pixels from sufficiently detailed visual codes.
  • Diffusion decoder: generates an image conditioned on higher-level representations.

(a) Diffusion as the complete backbone

Here both text and image representations are corrupted and then jointly denoised.

Why it occurs:

Diffusion can use bidirectional context: every uncertain token or image region can be refined using information from the entire sample. This is natural for images because the left and right sides of an image must remain globally consistent.

Benefits:

  • Parallel refinement rather than strict left-to-right generation.
  • Strong global image composition.
  • Text and image can mutually condition each other during denoising.
  • The model can revise earlier uncertain predictions.

Limitations:

  • Text generation is less natural than with AR language models.
  • Multiple denoising steps can be expensive.
  • Discrete text diffusion lacks some mature AR features, including straightforward KV caching and end-of-sequence handling.

The paper reports these benefits as synchronized multimodal generation and stronger cross-modal alignment, but also notes current efficiency and training difficulties. Paper, Section 3.1

(b-1) AR model with pixel encoding

image → VAE/VQGAN → visual tokens → AR model → visual tokens → pixel decoder
text  → tokenizer ────────────────→ AR model → text tokens

The image becomes a sequence of codes, almost as if it were another language.

Why it occurs:

This is the simplest way to reuse an LLM architecture. Text and image tokens can be concatenated into one sequence and trained using the same next-token objective.

Benefits:

  • One backbone and one causal modeling framework.
  • Natural interleaved output: text → image → text.
  • Pixel tokens preserve reconstructable details.
  • A lightweight decoder is sufficient because the codes already contain pixel information.
  • Existing LLM training infrastructure can be reused.

Problems:

  • A high-resolution image can require thousands of tokens.
  • Sequentially generating those tokens is slow.
  • Reconstruction-trained tokens know texture and color, but may not represent concepts well.
  • Text–image alignment is therefore harder.

This explains the move from pixel encoding toward semantic encoding. Pixel-encoding discussion

(b-2) AR model with semantic encoding

image → CLIP/SigLIP → semantic tokens → MLLM
                                      ↓
                              diffusion decoder → image

Why the pixel encoder is replaced:

Pixel tokens are poor “language.” A semantic encoder is trained to map visual content closer to textual meaning—for example, making the visual representation of a dog close to the language concept “dog.”

Benefits:

  • Better visual question answering and reasoning.
  • Stronger text–image alignment.
  • Usually fewer, more informative tokens.
  • Easier for the LLM to use visual information compositionally.
  • Good semantic control of generated images.

Why a diffusion decoder is often added:

Semantic features are not invertible. A CLIP feature might retain “a brown dog on grass” but discard exact fur patterns and pixel positions. A simple pixel decoder cannot recover missing details. Diffusion supplies a learned image prior that fills in plausible texture, lighting, and geometry.

Problems:

  • Exact source-image details may be lost.
  • Poorer spatial correspondence and fine-grained editing.
  • The diffusion decoder may generate a plausible but slightly different image.
  • Separately trained semantic encoders and diffusion decoders can have representation mismatch.

So this change improves meaning but weakens exact reconstruction. Semantic-encoding discussion

(b-3) Learnable-query encoding

dense image features + N learned queries
                 ↓ cross-attention
       N compact, content-aware tokens
                 ↓
               MLLM → diffusion decoder

Why it occurs:

A fixed patch grid treats every region as equally important. Learnable queries instead act like information-seeking probes: one query may extract objects, another relations, another global layout.

Benefits:

  • Compresses a large image into a small number of tokens.
  • Tokens are content-dependent rather than fixed spatial patches.
  • Reduces the AR sequence length.
  • Can be trained jointly for semantic alignment and reconstruction.
  • Provides an interface between a frozen vision encoder and an LLM.

Problems:

  • A small fixed query set becomes an information bottleneck.
  • Complex scenes may contain more information than the queries can capture.
  • Increasing the number of queries increases attention and memory cost.
  • Frozen encoders may not adapt sufficiently to new tasks.

It is therefore a learned compromise between dense pixel tokens and highly abstract global semantic features. Learnable-query discussion

(b-4) Pseudo-hybrid encoding

understanding task: image → semantic encoder → MLLM
generation task:    image → pixel encoder    → MLLM → image decoder

Why two encoders appear:

No single encoder is currently optimal for both understanding and reconstruction. Models such as Janus therefore “decouple” the pathways:

  • semantic features for understanding;
  • pixel codes for generation.

Only the appropriate branch is normally active for a task.

Benefits:

  • Each task gets a specialized representation.
  • Less destructive interference between understanding and generation objectives.
  • Can reuse strong pretrained encoders and decoders.
  • Modular and comparatively easy to train.
  • Only one encoder may need to run at inference time.

Problems:

  • It is only partially unified.
  • Generation may not directly benefit from the semantic encoder.
  • Understanding may not have access to fine visual details.
  • Knowledge learned in one pathway may not fully transfer to the other.

This architecture exists mainly because specialization is currently easier and more stable than forcing one visual representation to do everything.

(b-5) Joint-hybrid encoding

             ┌→ semantic encoder → semantic tokens ┐
image ───────┤                                    ├→ MLLM
             └→ pixel encoder    → pixel tokens ───┘

This is the stronger form of hybrid encoding: both types of information are available simultaneously.

Benefits:

  • Semantic tokens supply objects, relationships, and language alignment.
  • Pixel tokens supply position, texture, color, and identity.
  • Better suited to image editing, where the instruction must be understood while unchanged regions must be preserved.
  • Potentially improves both prompt adherence and visual fidelity.
  • Can support either pixel or diffusion decoders.

Problems:

  • Longer sequences and greater memory consumption.
  • Redundant information between two token streams.
  • The representations may disagree.
  • Fusion along the sequence or channel dimension requires careful alignment.
  • Training signals from understanding and generation can conflict.

Thus, joint hybrid encoding is more expressive but considerably more difficult and expensive. Hybrid-encoding discussion

(c-1) Fused AR + diffusion with pixel encoding

text:  causal AR next-token prediction
image: bidirectional diffusion/flow denoising
                 ↑
       shared or connected backbone

This is one of the most important architectural changes.

Why it occurs:

Generating an image patch-by-patch with AR modeling is analogous to painting an image permanently from the top-left corner to the bottom-right. Early mistakes cannot easily be revised, and distant areas cannot coordinate during generation.

Diffusion instead updates the entire visual latent grid repeatedly. Meanwhile, text remains autoregressive because sequential generation works extremely well for language.

Benefits:

  • Preserves the reasoning and language abilities of a pretrained LLM.
  • Produces images non-sequentially with stronger global coherence.
  • Continuous VAE latents preserve more nuance than a small discrete codebook.
  • Text can provide symbolic planning and control while diffusion handles rendering.
  • One transformer may share higher-level knowledge across both objectives.

Typically the model uses:

  • causal attention and cross-entropy loss for text;
  • bidirectional attention and denoising/flow loss for images.

Problems:

  • Multiple image-denoising steps increase latency.
  • Pixel latents still do not align naturally with language semantics.
  • Balancing AR and diffusion losses is difficult.
  • Shared parameters can experience conflicting gradients.

The paper describes this as an effective trade-off between symbolic control and visual fidelity. Fused AR–diffusion discussion

(c-2) Fused AR + diffusion with hybrid encoding

This combines both major solutions:

semantic representation → understanding/reasoning
pixel representation    → detailed image state
AR process              → language and planning
diffusion/flow process  → globally coherent rendering

Benefits:

  • Strong language reasoning from AR.
  • Strong image generation from diffusion.
  • Language-aligned visual understanding from semantic features.
  • High-fidelity reconstruction and editing from pixel features.
  • Potentially the best architecture for “look at this image, reason about it, and generate an accurately edited version.”

Costs:

  • Two encoders plus two kinds of generative objectives.
  • Highest training and inference complexity.
  • Hard alignment between semantic and pixel representations.
  • More data and careful optimization are required.
  • Improvements to generation can sometimes reduce understanding performance, or vice versa.

The overall design progression

The architectural motivation can be summarized as:

AR + pixel tokens
    │ solves: one unified sequence
    │ problem: weak semantics and slow image generation
    ▼
AR + semantic tokens
    │ solves: understanding and language alignment
    │ problem: loses exact visual detail
    ▼
learnable queries / dual encoders
    │ solves: compression or task specialization
    │ problem: bottlenecks or incomplete sharing
    ▼
joint hybrid encoding
    │ solves: meaning + detail
    │ problem: cost and representation alignment
    ▼
AR + diffusion hybrid
      assigns each modality its most suitable generator:
      AR for language, diffusion for images

The key takeaway is that these changes do not simply add more modules for their own sake. Every added branch repairs a specific information loss:

  • semantic encoder repairs poor language alignment;
  • pixel encoder repairs loss of visual detail;
  • learnable queries repair excessive token length;
  • diffusion decoder repairs the inability to reconstruct pixels from semantic features;
  • AR + diffusion fusion repairs the mismatch between sequential language generation and spatial image generation.

There is currently no universally best architecture. For multimodal reasoning, semantic AR designs can be preferable; for exact editing and high-quality generation, hybrid AR–diffusion designs are generally more suitable, despite their additional cost.

How the conditioning works

The diffusion decoder generates an image, while the learnable-query outputs tell it what image to generate.

The key is that the conditioning source depends on the task.

Inside the diffusion decoder

At diffusion step t:

ε̂ = εθ( zt,  t,  C )

where:

  • zt: the current noisy image latent;
  • t: diffusion timestep;
  • C: conditioning tokens;
  • ε̂: predicted noise to remove.

Here, C can be the compact tokens produced from the learnable queries.

The cross-attention direction is now reversed compared with the encoder:

Diffusion decoder:

noisy image-latent tokens → Queries (Q)
conditioning tokens       → Keys and Values (K, V)

So each noisy image patch asks:

“What visual content should I construct here, given these semantic conditions?”

Case 1: Reconstructing an input image

During tokenizer/decoder training:

Original image
    ├→ semantic vision encoder
    │       ↓
    │  dense visual features
    │       ↓ learned queries attend to features
    │  compact semantic tokens C
    │
    └→ VAE encoder → clean latent z₀ → add noise → zₜ

Diffusion decoder(zₜ, timestep t, condition C)
                       ↓
              reconstructed image

The conditioning represents the original image’s content:

  • which objects are present;
  • their approximate appearance;
  • spatial relationships;
  • scene composition.

The noisy latent supplies the image state being denoised. The compact query tokens guide what that state should become.

During training, the target is normally the same original image. This teaches the decoder:

“Given these semantic tokens, generate an image that matches their content.”

Case 2: Text-to-image generation

At inference there is no input image to encode. Instead, the MLLM predicts image-conditioning tokens from the text:

"A red car beside a lake"
            ↓
           MLLM
            ↓
predicted visual-conditioning tokens Ĉ
            ↓
random-noise image latent z_T
            ↓
diffusion decoder conditioned on Ĉ
            ↓
generated image

So the flow is:

text  →  MLLM  →  Ĉ  →  diffusion decoder  →  image

The MLLM does not need to predict every pixel. It predicts a compact “semantic plan” for the image, while diffusion performs the detailed rendering.

The conditioning might communicate something like:

object:       red car
location:     foreground
background:   lake
lighting:     sunset
relationship: car beside lake

These are not necessarily explicit human-readable fields—they are learned vectors containing that information.

Case 3: Image editing

For editing, the condition can combine several sources:

Source image → query tokens ────────┐
                                    ├→ MLLM → conditioning C
Editing instruction: "make it blue" ┘

Source image latent/noisy latent ─────→ diffusion decoder
Condition C ──────────────────────────→ diffusion decoder
                                         ↓
                                    edited image

Here:

  • source-image query tokens describe what is in the original image;
  • text describes the requested change;
  • the source VAE latent may preserve exact spatial and pixel information;
  • diffusion produces the edited result.

The exact inputs vary by model. Some models condition only on semantic tokens; stronger editing systems often also provide source-image latents, masks, or other spatial controls.

Two different cross-attention operations

This is the part that can be confusing:

1. Visual compression

Learned queries Q
      cross-attend to
dense source-image features K,V
             ↓
compact visual tokens C

The learned queries extract information from an image.

2. Diffusion generation

Noisy image-latent patches Q
      cross-attend to
compact conditioning tokens C as K,V
             ↓
conditioned image-latent patches

The diffusion model uses that extracted—or MLLM-predicted—information to construct an image.

So the compact tokens sit between the two attentions:

source-image features
        ↓
[learnable queries extract information]
        ↓
compact visual tokens C
        ↓
[diffusion image latents attend to C]
        ↓
generated/reconstructed image

The condition is therefore not always an input image. It is a learned representation of the desired image:

  • derived from an image during reconstruction;
  • predicted from text during text-to-image generation;
  • derived jointly from an image and instruction during editing.
