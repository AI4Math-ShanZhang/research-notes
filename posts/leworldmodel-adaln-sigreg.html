LeWorldModel — AdaLN and SIGReg, in shapes

Paper: LeWorldModel: Stable End-to-End Joint-Embedding Predictive Architecture from Pixels — Lucas Maes*, Quentin Le Lidec*, Damien Scieur, Yann LeCun & Randall Balestriero (Mila / Université de Montréal, NYU, Samsung SAIL, Brown), March 2026, arXiv:2603.19312. This note is not a full analysis — it is the two mechanisms I had to work out tensor by tensor: how the action gets into the predictor (AdaLN) and how the anti-collapse term is actually computed (SIGReg), plus one thing that turned out to be unrelated.

📄 Paper Summary

The claim. LeWM is the first JEPA that trains stably end-to-end from raw pixels using only two loss terms: a next-embedding prediction loss and a regularizer forcing the latents to be Gaussian. No EMA teacher. No stop-gradient. No pretrained encoder. No auxiliary supervision. That drops the tunable loss hyperparameters from six to one versus the existing end-to-end alternative. 15M parameters, one GPU, a few hours, and it plans up to 48× faster than foundation-model world models.

Why this is surprising. Both sides of the prediction loss are live — the target embedding gets gradient too. Normally that collapses within minutes: map every image to the same vector and the loss is zero. SIGReg is the only thing preventing it. Everything else in the paper follows from that one substitution.

The model in shapes

Defaults: batch B = 128, sub-trajectory T = 4 frames, frame-skip 5 (each "action" is a block of 5 environment actions grouped together), 224×224 frames.

obs      (128, 4, 3, 224, 224)   raw pixels
actions  (128, 4, A)             A = one block of 5 env actions

ENCODER  ViT-Tiny, patch 14, 12 layers, 3 heads, width 192, ~5M params
  224/14 = 16  ->  16x16 = 256 patches + 1 CLS = 257 tokens
  take CLS only              -> (128, 4, 192)
  projector: 1-layer MLP + BatchNorm  -> z  (128, 4, d),  d = 192

PREDICTOR  6 layers, 16 heads, dropout 0.1, ~10M params, ViT-S style
  causal mask, history window 3 (PushT, OGBench-Cube) or 1 (TwoRoom)
  action enters via zero-initialized AdaLN at every layer
  -> projector -> ẑ  (128, 4, d)

LOSS  MSE( emb[:, 1:] , next_emb[:, :-1] )  +  0.1 * SIGReg(Z)

Why the extra projector after the CLS token

The paper says it is necessary, and the reason is geometric. The last ViT layer applies LayerNorm, which pins every embedding to zero mean and unit variance across channels — so every vector sits on a fixed-radius shell. A real Gaussian cloud has vectors of many different lengths. Under LayerNorm, SIGReg's target is literally unreachable and its gradient just fights the norm. The MLP + BatchNorm projector frees the geometry so SIGReg can shape the distribution.

Planning (separate stage, frozen weights)

Cross-Entropy Method: sample 300 candidate action sequences, roll each through the frozen predictor, score by ||ẑ_H − z_goal||², keep the top 30, refit the sampling distribution, repeat up to 30 iterations on PushT (10 elsewhere). Horizon 5 steps = 25 environment timesteps at frame-skip 5, receding-horizon MPC.

🖊 My Key Notes

Part 1 — AdaLN: how the action gets in

Plain LayerNorm scales and shifts with fixed learned vectors:

h = (x - mean) / std        per token, across the 384 channels
h = h * gamma + beta        gamma, beta learned once, same for every input

AdaLN keeps the same equation but predicts gamma and beta from the action. Different action → different normalization → different prediction. LeWM cites Peebles & Xie (DiT), so this is the adaLN-Zero recipe:

a_t   (128, 4, A)          the action block at each frame
  |   small MLP
  v
c     (128, 4, 384)        conditioning vector, ONE PER FRAME
  |   Linear, weights AND bias initialized to ZERO
  v
      (128, 4, 6*384 = 2304)
  |   chunk into 6 pieces of 384
  v
scale1, shift1, gate1, scale2, shift2, gate2     each (128, 4, 384)

Then inside each of the 6 predictor blocks:

h = LayerNorm(x)                      # elementwise_affine = FALSE
h = h * (1 + scale1) + shift1         # <-- action enters
x = x + gate1 * CausalAttention(h)    # <-- action gates the branch

h = LayerNorm(x)
h = h * (1 + scale2) + shift2
x = x + gate2 * MLP(h)

Where the middle dimension comes from

It is the predictor's sequence length: one token per frame. Two different numbers in the paper are easy to confuse:

NumberWhat it is
Sub-trajectory T = 4Frames + action blocks in the batch. This is the sequence length, so shapes read (128, 4, 384).
History length = 3How far back the causal mask lets each token look. Not a shape.
predictor sequence (4 tokens, one per frame):

  token:   z1      z2      z3      z4        each 384 wide
  action:  a1      a2      a3      a4        every frame has its OWN action
           |       |       |       |
       modulate modulate modulate modulate   token i gets action i's scale/shift/gate
           |       |       |       |
  output:  ẑ2      ẑ3      ẑ4      (dropped)
  target:  z2      z3      z4                3 pairs -> the MSE

causal mask, history window 3:
        z1  z2  z3  z4
  z1     ✓   ·   ·   ·
  z2     ✓   ✓   ·   ·
  z3     ✓   ✓   ✓   ·
  z4     ·   ✓   ✓   ✓      <- z1 falls out of the 3-frame window
The modulation is per token, not broadcast. This is where LeWM differs from DiT. In DiT the condition is one diffusion step + one class label for the whole image, so c is (B, 384) and gets broadcast across all 256 patch tokens. Here frame 2 gets action 2 and frame 3 gets action 3 — there is nothing to broadcast.

Why zero-init, and why 1 + scale

At step 0 the linear outputs all zeros, so:

scale = 0  ->  h * (1 + 0) = h          no modulation
shift = 0  ->  + 0                      no shift
gate  = 0  ->  x = x + 0 * Attn(h) = x  the block is the IDENTITY

The predictor starts as a pass-through. It first learns "how does this world move on average," then gradually learns "how does my action change it." That is what the paper means by action conditioning impacting training progressively.

The 1 + is the part that is easy to miss. Written as h * scale, zero-init would multiply the features by zero and destroy the signal. The 1 + makes zero mean "do nothing" instead of "erase everything."

Small worked example (4 channels)

x            = [ 2.0,  0.0, -1.0,  3.0 ]
mean = 1.0, std = 1.581
LayerNorm(x) = [ 0.632, -0.632, -1.265, 1.265 ]

action "push right" -> MLP gives
  scale = [0.5, -0.3, 0.0, 0.2]
  shift = [0.1,  0.0, -0.2, 0.0]

h = norm * (1 + scale) + shift
  = [0.632*1.5 + 0.1,  -0.632*0.7,  -1.265*1.0 - 0.2,  1.265*1.2]
  = [ 1.048, -0.442, -1.465,  1.518 ]

Action "push left" produces different scale/shift → different h → different attention → different predicted next latent. Same image, different future. That is the entire conditioning mechanism.

Q: Does that LayerNorm still have its own gamma and beta?

No — in DiT's implementation it is literally nn.LayerNorm(dim, elementwise_affine=False). Because the scale and shift ARE the gamma and beta. They did not disappear; they got promoted from fixed parameters to network outputs. That is exactly what "Adaptive" in Adaptive LayerNorm means.

plain LayerNorm:  h = normalize(x) * gamma      + beta
                                     ^^^^^        ^^^^
                                     learned once, same for every input

AdaLN:            h = normalize(x) * (1 + scale) + shift
                                     ^^^^^^^^^^^   ^^^^^
                                     predicted from the action, different every step

Keeping both would give h = (normalize(x)*gamma + beta) * (1 + scale) + shift — two stacked per-channel scalings, redundant, and it breaks the clean zero-init story.

Q: Why two scale/shift pairs instead of one?

Because a pre-LN transformer block already has two LayerNorms. AdaLN did not add a second one; it made both existing ones adaptive.

plain pre-LN block:
h = LayerNorm_1(x)          <- LN number 1
x = x + Attention(h)
h = LayerNorm_2(x)          <- LN number 2
x = x + MLP(h)

So "two" is not a design choice — using one would mean stripping the affine off one of the two norms. And they should differ anyway, for three reasons:

  1. The sub-layers do different jobs. Attention decides where to look (which past frame matters); the MLP decides what this state becomes. "Push hard right" wants attention to sharpen onto the newest frame (fast motion makes old frames stale) and the MLP to bias the position channels rightward. One shared knob would force those two to fight.
  2. The second norm sees a different tensor. x = x + gate1 * Attn(h) runs in between, so the per-channel statistics have changed. A correction tuned pre-attention is wrong post-attention.
  3. Sharing saves almost nothing. The linear would emit 3*384 instead of 6*384, and you lose the ability to steer the two paths separately.

That said, 6 chunks doubles the modulation linear from ~442k to ~884k parameters per block, which is not free at this model size. The paper only says "AdaLN applied at each layer, parameters initialized to zero" — it does not spell out whether the modulation MLP is per-layer or shared, so the exact parameter split would need the code.

Q: Why AdaLN rather than just concatenating the action as an extra token?
  1. Attention can ignore an extra token by driving its weight to ~0. Modulation multiplies every channel of every token — it is unavoidable.
  2. No sequence cost. One action token per frame would double a 4-token sequence to 8.
  3. The action is a property of the transition, not an object in the scene. You do not want to look at it; you want it to bend the computation.
  4. Zero-init gives a safe start, which you cannot do with a concatenated token — it is there from step 1.

Part 2 — SIGReg: the anti-collapse term, step by step

The goal: make the latents look like an isotropic Gaussian — round, spread out, no dead direction. The problem: testing "is this 192-dimensional cloud Gaussian?" is hard, because classical normality tests are built for one dimension.

Cramér–Wold theorem. Two distributions in d dimensions are identical if and only if all their 1-D projections are identical. So one hard d-dim test becomes many easy 1-D tests — and you cannot cheat by being Gaussian along only a few directions, because "all directions" closes that door.

The shapes

Z has shape (N, B, d) — the pseudocode gets it with emb.transpose(0, 1), turning (B, T, D) into (T, B, D).

Z = (3, 128, 192)

STEP 1 — sample M = 1024 random directions
  G ~ Normal(0, 1)          (192, 1024)
  U = G / column norms      (192, 1024)   each column is a unit vector on the sphere

STEP 2 — project
  h = Z @ U
  (3, 128, 192) @ (192, 1024)  ->  h = (3, 128, 1024)

  Read this carefully: for EACH timestep n and EACH direction m you now hold
  128 plain real numbers — the batch squashed onto one line. The 192 dims are gone.

STEP 3 — Epps-Pulley on each 1-D sample, at K = 17 knots t_1..t_K
  for each knot t:
    ECF real = mean over b of cos(t * h[n, b, m])
    ECF imag = mean over b of sin(t * h[n, b, m])
    target   = exp(-t^2 / 2)        (a Gaussian's characteristic function; imag part 0)
    error(t) = (ECF real - target)^2 + (ECF imag)^2

  (3, 128, 1024) --evaluate at 17 knots, average over b--> (3, 1024, 17)

STEP 4 — integrate over t
  weighted sum over the 17 knots, weight w(t) = exp(-t^2 / (2*lambda^2))
  (3, 1024, 17)  ->  (3, 1024)

STEP 5 — average
  mean over M=1024  ->  (3,)
  mean over N=3     ->  a single scalar        "step-wise SIGReg"

FINAL  loss = MSE_prediction + 0.1 * that scalar

What t means, and how it differs from K

t is a value; K is how many values of t you use.

The Epps–Pulley test compares two characteristic functions — the Fourier transform of a distribution, phi(t) = average of exp(i*t*h). So t is a frequency: small t probes the coarse shape (where the mass is, how wide), large t probes fine detail (spikes, gaps, hidden discreteness). The test wants agreement at every t, which is an integral from −∞ to ∞. You cannot evaluate infinitely many, so you pick K specific values — the knots — and do a weighted sum instead. Since the weight w(t) is itself a Gaussian bump, Gauss–Hermite quadrature places those 17 points optimally, which is why K barely matters.

Notation trap: the lambda inside w(t) is not the lambda = 0.1 loss weight. Same letter, different thing.

Worked example — one direction, 4 samples

h = [0.5, -0.3, 1.2, -0.8]

At knot t = 1.0:
  cos(1.0 * h) = [0.8776, 0.9553, 0.3624, 0.6967]  -> mean = 0.7230   (real)
  sin(1.0 * h) = [0.4794, -0.2955, 0.9320, -0.7174] -> mean = 0.0996  (imag)
  target: exp(-1.0^2 / 2) = 0.6065,  imag 0

  error = (0.7230 - 0.6065)^2 + (0.0996)^2
        = 0.01357 + 0.00992 = 0.0235

At knot t = 0:
  cos(0 * h) = [1,1,1,1] -> mean = 1
  sin(0 * h) = [0,0,0,0] -> mean = 0
  target: exp(0) = 1
  error = 0

The error at t = 0 is always exactly zero, for any data at all. That knot carries no information — which is why the knots must spread away from zero, and why Gauss–Hermite (symmetric around zero, at useful distances) is the right scheme.

Why this actually stops collapse

Suppose the encoder collapses: every z becomes the same vector c. Then h is a constant — 128 identical numbers. Its characteristic function is exp(i*t*const), which has magnitude 1 at every t and never decays. The Gaussian target exp(-t²/2) decays fast. So the gap is huge at every knot and the penalty explodes. Collapse is the single worst thing you can do under this loss — which is why LeWM survives with no EMA and no stop-gradient.

Why M = 1024 barely matters, and why the cost is low

You are Monte-Carlo estimating an average over the whole sphere; 1024 samples already estimate that average well, and directions are resampled every training step, so over 20k steps the model effectively sees far more than 1024.

Cost: the biggest tensor is B × M × K = 128 × 1024 × 17 ≈ 2.2M numbers per timestep, and everything is matmul, cos, sin, sum. Compare with covariance-based anti-collapse (VICReg-style), which builds a d × d matrix and often needs eigenvalues or an inverse — O(d²) memory, O(d³) compute, and unreliable when d is large relative to B. SIGReg never forms a covariance matrix. That is the "scalable" claim.

Part 3 — CEM has nothing to do with SIGReg

They never run at the same time.

backprop -> update weights        CEM searches an action sequence
CEM does not exist here           SIGReg does not exist here
SIGRegCEM

What it changesnetwork weightsan action sequence

Two traps make them look related:

  • The name. "Cross-Entropy Method" has nothing to do with cross-entropy loss in classification. It got the name from its original derivation (minimizing KL between the sampling distribution and the ideal one). In practice it is just sample → keep the elite → refit → repeat.
  • Both mention Gaussians, but in opposite directions and in different spaces. SIGReg pushes data (embeddings in R¹⁹²) toward a Gaussian. CEM fits a Gaussian to the elite action sequences (in R5×A). SIGReg shapes the data; CEM fits a proposal to data it drew itself.
The one thread that does connect them, indirectly: CEM's cost is plain L2 distance in latent space. That cost only means something if the latent space is well spread and round. A collapsed latent would score every candidate the same and CEM would search noise. So SIGReg makes CEM's objective usable — through the quality of the representation, not through any shared math.
