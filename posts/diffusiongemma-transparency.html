How Transparent is DiffusionGemma?

Paper: How Transparent is DiffusionGemma? — Joshua Engels, Callum McDougall, Bilal Chughtai et al. (Google DeepMind, June 2026), arXiv:2606.20560. The model itself has no paper — only a model card, so this paper's Appendix A is currently the most detailed public description of DiffusionGemma's architecture.

✅ In one line

DiffusionGemma passes a dense vector between denoising steps, which naively makes it 28.6× more opaque than autoregressive Gemma 4 — but that vector is built as softmax(logits) · WE, so it is structurally made of token directions. Squeeze it down to ~8 tokens per position and capabilities are unchanged; read those tokens and they are mostly guesses at the current and neighbouring final tokens. Opaque serial depth drops to 1.1×.

📄 Paper Summary

The question

Autoregressive models reason in visible chain-of-thought text, and that visibility is load-bearing for safety — you can hand the CoT to a monitor and ask it to look for reward hacking, prompt injection, or scheming. Text diffusion breaks the assumption: DiffusionGemma refines a whole canvas of C tokens for T steps, and part of what crosses each step boundary is not language. So: does it still "think in English"?

Three axes of transparency

AxisQuestionVerdict
Opaque serial depth How much serial computation happens between interpretable nodes? 28.6× naively → 1.1× if the bottleneck is readable
Variable transparency Can we read an intermediate snapshot of the state? Yes, mostly (§3)
Algorithmic transparency Can we reconstruct the process from those snapshots? Harder — six diffusion-specific behaviours (§5)
Monitorability Can a monitor extract useful information from outputs? Similar to Gemma 4 (§4)

Two quantities cross each step boundary — the canvas tokens o (readable, it's just text) and the self-conditioning matrix S (C × dmodel, not readable by default). S is the whole problem.

§2 — Opaque serial depth

Compile the model (including sampling) to a Boolean circuit, mark the interpretable nodes, take the longest path containing none. Measured at 256k context:

ModelEmpirical (UB)Asymptotic
Gemma 4 26B A4B21,235O(L·(log N + log D))
DiffusionGemma — interpretable bottleneck23,571 (1.1×)O(L·(log N + log D + log C))
DiffusionGemma — uninterpretable bottleneck608,016 (28.6×)O(T·L·(log N + log D + log C))

The 28.6× uses the worst case T = 48; adaptive stopping normally halts at 12–16 steps, so in practice it's about a third of that. Everything hinges on which row you're entitled to quote — hence §3. (Tool: google-deepmind/serial_depth.)

§3.1 — Squeezing the bottleneck

S is built from all |V| ≈ 262k vocabulary entries. Restrict it and see if the model still works:

S' = W_E · softmax( f(ℓ̂) )

f_k :  keep the top k logits;                  squash the rest to a constant c
f_p :  keep logits with probability >= p;       squash the rest to a constant c

c = ln( S_rest / (|V| - |kept|) )   chosen so the KEPT tokens' probabilities are EXACTLY preserved

Worked example, V = 6, Z = [4.0, 3.0, 1.0, 0.0, -1.0, -2.0], fk=2:

probs   = [0.6920, 0.2546, 0.0345, 0.0127, 0.0047, 0.0017]
S_rest  = 4.221            c = ln(4.221/4) = 0.0538
probs'  = [0.6920, 0.2546, 0.0134, 0.0134, 0.0134, 0.0134]
          └─ unchanged ─┘  └──── flattened, same TOTAL mass ────┘

Result (Fig. 2): k = 8 and p = 0.03 match baseline on Natural2Code, LiveCodeBench, AMC/AIME, IMO and GPQA. Since probabilities sum to 1, a p-threshold admits at most 1/p = 33 tokens — so the bottleneck really is O(few) tokens, against a 262,144-entry vocabulary.

Note: this fp is not nucleus sampling. Nucleus keeps the smallest set whose cumulative mass reaches p; here it's a per-token threshold (closer to min-p / epsilon sampling). That's why the paper says decreasing p improves performance — a lower bar admits more tokens.

§3.2 — Are those tokens interpretable? (Fig. 3)

800 WildChat prompts, 1024 generated tokens (4 canvases), T = 48, no early stopping. Every surviving token is sorted into one of five categories, by priority, against the final output:

1. Final Token          exact match at this position i
2. Adjacent Token       exact match at a final token within ±10 positions
3. Similar to Final     top-50 cosine neighbour (Gemma 4 31B embeddings) of the final token at i
4. Similar to Adjacent  same, but for a nearby position
5. Other                ← the grey band. This is just the else branch.

The distance gradient is itself informative: light shades (distance 1–10) are thickest at early steps and collapse to distance 0 as denoising proceeds. That's token smearing, visible as a colour gradient.

§4 — Monitorability

Adapting the eval suite of Guan et al. (2025) — intervention, process, and outcome-property categories, scored by G-mean². Averages: Gemma 4 ≈ 0.82, DiffusionGemma ≈ 0.78. Similar.

Two caveats the paper flags itself. (1) These rollouts span many canvases, and reasoning between canvases is autoregressive — so the similarity is partly measuring AR behaviour, not diffusion behaviour. (2) DiffusionGemma's CoT is ~3× shorter (8,447 vs 24,392 characters, Fig. 5), and longer CoT is generally more monitorable — so this confounder handicaps DiffusionGemma, and it matched anyway.

§5 — Six diffusion-specific reasoning behaviours

PhenomenonWhat happens
Early length prediction
§5.1.1		 After one step, padding probability is ~100% beyond position 55; the answer converges to 50 tokens. Padding probs are monotone in position, so they read as a CDF over length: Et[L] = Σi (1 − pt(i)). By step 2 it's an almost perfect predictor. The only quantified result in §5.
Retroactive self-correction
§5.1.2		 "Squares between 400 and 800? State your answer first, then reason." Step 4: answer 9 (moderate confidence). Steps 5–6: computes √400 = 20, √800 ≈ 28.28. Step 7: reaches backwards and corrects to 8. Impossible autoregressively.
Non-AR code generation
§5.1.3		 Skeleton-first: function name and block delimiters → core loop logic → then docstring, variable inits and comments, which appear earlier in the file.
Token smearing
§5.2.1		 Knows what, not where: mass for " bracket" spread across a whole cluster of docstring slots before locking in. Same for newlines and commas.
Sequence smearing
§5.2.2		 Step 3 holds "There are **12** perfect squares…" and "There are **9** perfect squares…" simultaneously — the whole sentence at two offsets. Step 4 collapses to one.
Intermediate context reasoning
§5.3		 Fibonacci with "replace any units digit 3 with Gold". Step 2: 2, 1, 3, , , — Step 3: 2, 1, Gold, 4, 7. The 3 was needed to compute 4 and 7, and never appears in the output. Gemini 2.5 Pro can't do this task without CoT at all.

🖊 My Key Notes

1. What S actually is, in one formula

S_t = softmax( ℓ_t / τ_t ) @ W_E          shape (C, V) @ (V, d_model) → (C, d_model)

so   S[i] = Σ_v  P[i,v] · W_E[v]          a convex combination of token embeddings

Each row is a soft embedding — a probability-weighted blend of the vocabulary embeddings at that position. If the distribution is one-hot on "cat", S[i] = W_E[cat] exactly. As it spreads out, S drifts into the interior of the embedding convex hull. So read S as "a fuzzy token", and how fuzzy is exactly the model's uncertainty.

Concretely: position 5 has P(cat)=0.5, P(dog)=0.4, P(bird)=0.1, and sampling picks "dog". A vanilla masked dLLM forwards only the token dog — the 0.5 on "cat" is gone forever. DiffusionGemma forwards dog and S[5], so the next step still knows it was torn.

Why S₀ = 0

At step 0 there is no previous prediction to condition on. S enters via embeddings + GatedMLP(S), and a gated MLP maps 0 → 0, so the first pass runs on the prompt plus the random canvas alone. This is the standard self-conditioning recipe from Chen et al.'s Analog Bits: during training you drop the self-conditioning input some fraction of the time by zeroing it, so zero is the in-distribution encoding of "no signal". The paper only states the zero-init; the rationale is inherited convention.

2. Why self-condition at all — and why this model needs it most

(a) Discrete sampling destroys nearly everything. A step computes C × 262k numbers of belief; sampling collapses each row to one integer. S is a cheap side channel that lets the distribution survive.

(b) Renoising means S is the only memory. This is the DiffusionGemma-specific reason. EB sampling replaces high-entropy positions with a uniformly random token — bit-for-bit identical to what that slot held at step 0. Without S, six steps of work at that position are simply gone; the model can't tell "I've been agonising over this slot" from "I've never looked at it". S is what makes renoising recoverable rather than amnesiac.

(c) Fewer steps. T is budgeted at 48 but adaptive stopping halts at 12–16. Each step removed is a full 26B forward pass saved — most of where the "4× faster" claim comes from.

3. The design choice that saves the whole paper

They could have forwarded the raw residual stream — more information, easier to implement. Forcing it through softmax(ℓ) @ W_E constrains the channel to the convex hull of token embeddings. It can only express "a mixture of tokens". It cannot express arbitrary latent content, because it is structurally built out of vocabulary directions.

That capacity limit is what makes the logit lens work, and it's why top-8 truncation costs nothing: there was never more than ~8 tokens of meaning in there. The paper is explicit that this is load-bearing — "DiffusionGemma has a projection in intermediate layers that biases the vector that gets passed between denoising steps towards the embedding vectors" — and that a differently-trained future model, or one under heavy outcome-based RL, could lose it.

Gemma ties its embeddings

WE is the ordinary learned embedding table, reused — no new embedding parameters. Since the Gemma family ties input and output embeddings, Eq. 1 is a clean round trip: h →WEᵀ→ logits →softmax→ P →WE→ S, out of embedding space and straight back in. That's why adding S to Embed(o) is type-correct rather than arbitrary.

4. The OOD caveat in §3.1, and why the bias is in their favour

After fk, all ~262,000 discarded tokens have identical probability. Real LM tails are never flat — they're heavy and semantically structured, concentrated on near-synonyms of the winner. So the tail contribution to S becomes:

naturally:  ≈ 0.0345·emb(token2) + 0.0127·emb(token3) + …   concentrated, related tokens
after f_k:  ≈ 0.0535 · (mean embedding of the ENTIRE vocabulary)   ← a direction never seen in training

So the ablation does two things at once: (1) removes tail information — what they want to measure — and (2) injects a vocabulary-centroid artifact — pure damage. You can't separate them, so the measured degradation is an upper bound on the true cost.

Why this makes the result stronger, not weaker

measured damage ≥ true information loss, and measured damage ≈ 0. A pessimistic method that still reports no damage gives a stronger conclusion than an unbiased one. If the bias ran the other way, the 28.6× → 1.1× result would be suspect. Flagging the flaw and using the method anyway is the right call here.

5. Lock-in is the unifying mechanism of §5 — and it's untested

It shows up three separate times as the failure mode: self-correction fails on lock-in (§5.1.2), the "Gold" substitution fails on lock-in (§5.3), and sequence smearing resolves by locking in (§5.2.2). The paper's hypothesis is a race condition:

process A:  entropy at the answer slot falls below the EB threshold   (commitment)
process B:  the reasoning region converges                           (computation)

B before A  →  correction works
A before B  →  lock-in, wrong answer is permanent

The load-bearing detail in the success case is that the answer was at "moderate confidence" at step 4 — high enough entropy to stay renoisable. Had it been confident, EB would have kept it and the reasoning at steps 5–6 would have had nothing to correct.

Why a token shift is especially hard: the canvas has fixed slots, so 12 → 9 displaces everything downstream by one position. But EB sampling accepts positions independently by entropy and refuses to renoise confident ones — an independent per-position rule structurally cannot coordinate a block move. Which means the whole block must be uncertain simultaneously… which is exactly what sequence smearing provides. §5.2.2 is the mechanism that makes §5.1.2's success case possible; lock-in is what happens when the smearing collapsed too early. The paper doesn't connect these two sections, but they're the same phenomenon from opposite sides.

The tension nobody resolves. EB sampling exists for speed — commit confident positions early so you finish in 12–16 steps instead of 48. But "commit confident positions early" is precisely the mechanism that causes lock-in. The sampler's speed feature and its correctness failure are the same mechanism, and γ = 0.1 plus the τ: 0.8 → 0.4 anneal are the knobs sitting on that tradeoff. No experiment in the paper touches either.

6. The sequence-smearing deflation is stronger than it looks

The paper says the model uses smearing "for spacing, not for storing multiple semantically different options at once." Decompose the canvas and you see why:

slot:   1      2     3    4    5    6        7        8        9
A:      There  are   **   1    2    **       perfect  squares  between   (12)
B:      There  are   **   9    **   perfect  squares  between  400       (9)
        └── same ──┘  ↑    └────────── offset by one ──────────────┘
                   differs

Slot 4 holds genuine semantic uncertainty (12 vs 9) — but that's ordinary token-level uncertainty at a single position, which an AR model has too. Slots 5+ are the actual sequence smearing, and they contain no semantic alternatives at all — the same continuation twice, mechanically displaced.

So the novel diffusion mechanism is doing zero semantic work. It's bookkeeping the layout consequence of a perfectly ordinary one-token uncertainty.

Also worth noticing: the example only produces smearing at all because 12 and 9 straddle the 9→10 tokenization boundary. Torn between 8 and 5, both single tokens, there'd be no shift and no smearing. The trigger is narrow.

The experiment that would settle it. Their example is confounded — 12 and 9 differ in both value and token length. The clean test is two plausible answers of identical token length ("1066 or 1067?"), so any multi-slot superposition can't be explained by spacing. Not in the paper.

7. Versus LLaDA-style masked diffusion

selection ruleconfidence / randomEB entropy budget (γ = 0.1)

The deep reason for uniform instead of absorbing noise: with mask noise, an unmasked token is known clean and the model has no reason to reconsider it. With uniform noise there is no marker separating "corrupted" from "settled", so every position is permanently suspect and revision is native rather than bolted on. That is the architectural root of everything in §5.

And on remasking — masked dLLMs do remask (LLaDA's low-confidence remasking), but a remasked slot returns to [MASK], which carries zero information. The model must re-derive its belief from visible neighbours. A renoised DiffusionGemma slot holds a garbage token but still carries its full distribution in S. That's why the 9 → 8 correction has something to build on instead of starting over.

The trade, stated once

Every "concerning" mechanism in this paper is the same feature as a capability gain. S carried forward → superposition persists, self-correction possible / but the bottleneck isn't language. EB renoising → answers can be revoked / but lock-in. Sequence smearing → can realign a whole sentence in one move / but a beam the output doesn't show. DiffusionGemma can retroactively fix its answer precisely because it has the machinery that makes it less transparent than a masked dLLM. LLaDA is more transparent here largely by being less able.

8. What §5 does and doesn't establish

Only §5.1.1 is quantified (Fig. 7 sweeps requested sentence count 1→5). Everything else is one prompt plus a visualiser screenshot. So none of these findings come with a frequency — we don't know whether retroactive self-correction happens on 2% or 60% of answer-first prompts. They're existence proofs, and the paper is upfront about it ("initial evidence", "one possibility", "so far").

The one genuine control experiment is the Collatz case in §5.2.1. Smearing requires identity to be knowable before position — "bracket" will appear somewhere in the docstring, you just don't know which slot. In a Collatz sequence each value is computed from its immediate predecessor, so identity and index determine each other exactly and there is nothing to be positionally uncertain about. Predicted: no smearing. Observed: no smearing. That's what upgrades the smearing story from anecdote to causal claim.

A quietly reassuring corollary the paper leaves implicit: smearing appears exactly where content is predictable, which is where you least need to monitor. On genuinely sequential reasoning — the cases you most want to follow — DiffusionGemma behaves essentially autoregressively and the canvas reads left to right.

9. §5.3 is the only finding that actually hurts

Everything else in §5 is "unusual order, still readable". The Fibonacci "3 → Gold" case is different: the digit 3 is causally necessary for computing 4 and 7, and is absent from the final output. Monitor only the finished text and that computational step is invisible — you see "Gold" and have no way to know a 3 was ever there.

§4 found final-output monitoring is empirically sufficient. §5.3 shows that in principle it need not be. That gap is the paper's real contribution to the safety case, and it's the thread worth watching in the next generation of these models.
