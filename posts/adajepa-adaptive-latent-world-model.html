AdaJEPA — An Adaptive Latent World Model

Paper: AdaJEPA: An Adaptive Latent World Model — Ying Wang, Oumayma Bounou, Yann LeCun & Mengye Ren, June 2026, arXiv:2606.32026. Project page · Code. This note is the Q&A from working through it, so it dwells on the parts that tripped me up: what exactly the adaptation loss compares, and which weights move.

📄 Paper Summary

The problem. A latent world model lets you plan from images: encode the observation into a compact latent, roll the dynamics forward, pick the action sequence that gets closest to the goal. But after training, the model is frozen. At deployment the surface is stickier, the lighting is different, the object is a shape it never saw — and the model's predictions are quietly wrong for the rest of the episode.

The move. Stop freezing it. AdaJEPA does test-time adaptation inside the MPC loop: plan, execute the first action chunk, watch what actually happened, take one gradient step on the world model using that transition, then re-plan with the corrected model. No expert demonstrations, no reward labels — the environment supplies the supervision for free.

The planning objective (unchanged from a normal latent-MPC setup)

Given a goal image o_g encoded to z_g, MPC picks the action sequence minimising a latent goal-reaching cost over the horizon:

a*_(t:t+H-1) = argmin  SUM_(k=1..H)  α_k · d( ẑ_(t+k) , z_g )

with  d(ẑ, z_g) = || ẑ - z_g ||²      (squared Euclidean in latent space)

The adaptation loss

L_ada(B) = (1/|B|) · SUM over (o_i, a_i, o_(i+1)) in B  of

               loss(  f_θ( z_i , E_ψ(a_i) )  ,   sg( z_(i+1) )  )

where   z_i = E_φ(o_i)
SymbolWhat it is
BReplay buffer — transitions the robot actually experienced, just now.
o_i, a_i, o_(i+1)"I saw this, I did this, then I saw that."
E_φVisual encoder: image → latent state z.
E_ψAction encoder: raw action → an embedding the predictor can consume.
f_θPredictor / dynamics: (z_t, action embedding) → ẑ_(t+1).
sg(·)Stop-gradient — freezes the target so the encoder can't chase it.
lossLatent prediction loss; MSE in practice.

In words: compare what the model predicted the next latent would be against what the next latent actually turned out to be, and shrink the gap.

The formula is not new — and that's the point. The JEPA pretraining objective is L_pred = (1/K) Σ_k loss(ẑ_(t+k), z_(t+k)), the same quantity. The contribution is when and on what data it is applied: at test time, on the last handful of transitions the robot generated itself, between two MPC replans.

The algorithm

Results

Across goal-reaching tasks — built on DINO-WM's setup, e.g. PushT (circular pusher, T-shaped block, target pose) — planning success improves substantially with as little as one gradient step per replan, under both visual and dynamics shift. Trajectory plots show the prediction loss falling as the episode proceeds, and better planning following from it. Every adaptation variant tested (predlast+enclast, predictor-only, different layer choices, LoRA on the full model) beats the frozen model; the result is not very sensitive to which layers you pick.

🖊 My Key Notes

Why re-planning alone isn't enough — noise vs. bias

MPC already re-plans from a fresh observation every step, so the obvious objection is: doesn't that already fix everything? No, and the distinction is the reason this paper exists:

Random noiseSystematic bias
ExamplePosition sensor jitters ±0.3Model thinks a push moves the block 1.0; it really moves 0.6
Fixed by re-planning?Yes — errors average out, re-planning is a filterNo — every cycle is wrong in the same direction, forever
Re-planning corrects state error ("where am I"). It cannot correct model error ("what happens if I push"). A frozen world model plans with the same wrong equations at step 20 as at step 1. AdaJEPA's whole contribution is adding the missing row: use the transition you just observed to move the weights.

And it matters more than it sounds for contact-rich tasks. In PushT, a 0.4-per-step optimism means all of the sampled rollouts are wrong about where the block ends up, so the planner picks the wrong contact point, the block rotates the wrong way, and no amount of accurate position feedback rescues a plan built on wrong physics.

What the correction looks like, with numbers

Toy version: trained where a push moves the block 1.0, deployed on a stickier surface where it moves 0.6.

         L_ada = (1.00-0.60)² = 0.160     → one gradient step

         L_ada = 0.102                    → one gradient step

after ~6 replans the predictor has converged to ≈0.62 per push
MPC hands you the training data for free. Every executed action produces an (o, a, o') triple whether you want it or not — a free experiment, every control cycle. A frozen world model throws all of them away. That's the whole opportunity AdaJEPA picks up.

Q&A — the bits I had to straighten out

Q: So in a normal latent world model, the parameters never update?

Correct — and that's the baseline being argued against.

Q: Is z the action embedding?

No — z is the image embedding. Two separate encoders feed the predictor:

  image  o_i  --[ E_φ ]-->  z_i          ← state latent, this is "z"
  action a_i  --[ E_ψ ]-->  (action embedding, no z name)
                   │
                   ▼
       f_θ( z_i , E_ψ(a_i) )  =  ẑ_(i+1)  ← predicted NEXT image latent
                   │
                   ▼
       compare with  sg( z_(i+1) ) = sg( E_φ(o_(i+1)) )   ← ACTUAL next image latent

Both sides of the loss are image latents. The action never appears as a prediction target — you don't predict actions, you predict the consequence of actions. The action gets its own encoder purely as a formatting step: the raw action is a couple of numbers, z is a big feature vector, and E_ψ lifts one into a space the predictor can mix with the other.

Q: Does only the predictor change, or the encoder too?

Both — but only their last layers. And the ablation gives a principle worth keeping: fix the error where it enters.

Kind of shiftWhere the error entersWhat you need to adapt
Shape / dynamics (different geometry, more friction) The predictor — the representation is fine, "what happens next" is wrong Predictor alone suffices; freezing the encoder costs nothing
Visual / layout (lighting, texture, camera, background) The encoder — the image maps to a bad z in the first place Predictor-only is not enough; the encoder must move

At deployment you don't know which one you're facing, so updating both last layers covers both. The action encoder E_ψ is inside the formal set Ω ⊆ {φ, ψ, θ} but isn't touched by default.

Q: Why the stop-gradient?

Because if both sides of the comparison are learnable, there's a cheating solution: map every image to the same constant vector. Prediction becomes trivially perfect, the loss hits zero, and the model is useless — representation collapse, the classic joint-embedding failure. sg(z_(i+1)) pins the target as a fixed number for this step, so the predictor must come to the target rather than the target sliding toward the predictor. This matters precisely because the encoder is being updated too.

Nice empirical footnote: drop stop-gradient, update only last layers for one step, and performance is about the same. One gradient step on a few parameters simply doesn't have the room to collapse anything — the safety comes as much from the tiny update budget as from sg.

Q: Why "last layers" and not fine-tune the whole thing?

Five samples, one gradient step. That budget can recalibrate a readout; it cannot retrain a backbone, and trying would wreck the representation pretraining paid for. Think recalibration, not learning — nudging the output scale/offset to match what this environment is doing right now.

Cost-wise it's essentially free: one backward pass over a few layers, next to a full CEM/MPPI search over hundreds of rollouts. That's why "one gradient step" is the headline rather than a limitation.

Where it sits in the landscape

Two honest limits:

  • It only corrects the model where you've been. The buffer holds visited states; the planner still rolls out into states you haven't. Wrong there, and L_ada has nothing to say.
  • It fixes the dynamics, not the cost. If the goal latent z_g is a poor target, or the encoder puts two task-identical scenes far apart, better prediction doesn't rescue the plan.

Framed against the earlier notes: planning-based control has three ways to fail — a biased state estimate, a model that drifts over the horizon, and a cost function that doesn't mean what you think. The sampling-based planner is effectively an adversary against your own world model, since searching 1000 sequences is a very good way to find the region where the model is wrongly optimistic. AdaJEPA attacks the second failure directly: keep patching the model where you are currently standing, using data the control loop was generating anyway.

It also sits opposite the π-series bet. π0.6/π0.7 amortise everything into policy weights and do no search or adaptation at deploy time. AdaJEPA keeps the planner and keeps learning during the episode — paying compute at test time in exchange for recovering from shifts a frozen policy would just fail on.
