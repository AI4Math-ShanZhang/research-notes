Causal-JEPA and Slot Attention — objects as tokens

Paper: Causal-JEPA: Learning World Models through Object-Level Latent Masking, arXiv:2602.11389 (v2, May 2026), code at galilaigroup/cjepa. Background paper: Object-Centric Learning with Slot Attention — Locatello et al., NeurIPS 2020, arXiv:2006.15055. This note first explains slot attention (and the GRU inside it), then how C-JEPA builds, masks and predicts slot tokens.

📄 Paper Summary

Two stages

  1. Train the slot encoder, then freeze it. Main choice: VideoSAUR. Frozen DINOv2 ViT-S/14 gives 196 patches (384-d) per frame. They are projected to 128-d and grouped by slot attention (2 rounds) into N slots. Loss: reconstruct the DINOv2 features + a temporal similarity loss. No labels. Trained separately on each dataset (CLEVRER, Push-T), 100k steps. A SAVi encoder (CNN, 64×64, pixel reconstruction) is also used, to compare fairly with baselines.
  2. Train the predictor on the frozen slots. Slots are extracted once for every video and saved. Predictor: 6 layers, 16 heads, MLP 2048, 128-d tokens, 30 epochs, batch 256, one GPU. Actions and proprioception can be added as extra "auxiliary" tokens (small 1-D conv embedders).

Object-level masking

  • Every (time, slot) is one token. CLEVRER: 6 history + 10 future frames × 7 slots = 112 tokens.
  • The future slots of all objects are always masked (they are what we predict).
  • The chosen objects in M are also masked over the whole history, except at t0.
  • A masked token is not a blank vector. It carries the object's identity:
masked token  z̃_τ^i  =  φ( z_t0^i )  +  e_τ
                         "which object"   "which time"

The slots have no fixed order and no object position encoding, so without the anchor the model could not tell which hole belongs to which object.

Loss

L = mean over masked tokens of  || ẑ_τ^i − z_τ^i ||²
  = history part (fill hidden objects in the past)
  + future part  (predict all objects in the future)

Targets are the frozen encoder's real slots, so there is no EMA target encoder. At test time there is no history masking: the full history is given and only the future is predicted.

🖊 My Key Notes

Q1. What is slot attention?

It takes many feature vectors (patches) and groups them into K slots, each meant to be one object. No labels; the only training signal is reconstructing the input.

  1. Sample K slots from one learned Gaussian. No slot is "the kettle slot" in advance.
  2. query = W_q · slot, key = W_k · input, value = W_v · input.
  3. score = key · query / sqrt(D) → an N_patches × K table.
  4. Softmax over the slots, not over the inputs. Each pixel splits itself among the slots, so slots compete.
  5. For each slot, weighted mean of the values (divide by the column sum) = the update.
  6. slot = GRU(old slot, update), then slot = slot + MLP(LayerNorm(slot)).
  7. Repeat 2–6 for 2–3 rounds. Decode each slot to an image + mask, combine, and train on reconstruction.

Small example — 4 pixels, 2 slots; p1, p2 = red ball, p3, p4 = blue background:

        scores (A, B)   softmax over slots
p1      (2, 0)          A 0.88   B 0.12
p2      (2, 0)          A 0.88   B 0.12
p3      (0, 2)          A 0.12   B 0.88
p4      (0, 1)          A 0.27   B 0.73

slot A column = [0.88, 0.88, 0.12, 0.27], sum 2.15
mean weights  = [0.41, 0.41, 0.06, 0.13]   → slot A ≈ the ball
Weak points: K is fixed; slots have no order (video versions start each frame from the last frame's slots); slots often split or merge objects in cluttered real scenes.
Q2. What is GRU(old slot, update)?

A small learned unit that decides how much to change the slot. h (the GRU's "hidden state") is the old slot; x (the GRU's "input") is the attention update. Same vectors, GRU names.

z = sigmoid(Wz·x + Uz·h)          update gate, 0..1
r = sigmoid(Wr·x + Ur·h)          reset gate, 0..1
c = tanh(W·x + U·(r * h))         candidate
new slot = (1 − z) * h + z * c

Example: h = 0.5, x = 0.9, z = 0.3, c = 0.8 → new = 0.7 × 0.5 + 0.3 × 0.8 = 0.59. The slot moves part of the way.

  • Why tanh? It keeps c in −1..+1, so the mix of old and c stays bounded and cannot explode over many steps. It can go negative (sigmoid cannot), so features can move up or down. Sigmoid is kept for the gates.
  • r and z do different jobs. r = what the proposal is built from (use old memory or start fresh). z = how much of the final state the proposal replaces.
  • Why not just new slot = c? That is a plain RNN, and it works, but it rewrites the slot every round. A slot that is already right drifts: with noisy updates, 0.80 → 0.72 → 0.68 with c only, vs 0.80 → 0.79 → 0.78 with z = 0.1. The (1 − z) · h path is a direct copy path (like a ResNet skip), which also keeps gradients from fading through tanh.
Q3. How is the 16 × 7 slot grid built?

Slot attention runs frame by frame, over the 196 patches of one frame. Frames are linked because each frame's slots start from the previous frame's slots (through a small transition network).

frame 1: random start → slot attention → slot1 = ball₁, slot2 = bg₁
frame 2: start from (ball₁, bg₁)        → slot1 = ball₂, slot2 = bg₂
frame 3: start from (ball₂, bg₂)        → slot1 = ball₃, slot2 = bg₃

So slot k keeps tracking the same object. Stack 16 frames → 16 × 7 grid → flatten to 112 tokens, add the time embedding, then mask.

Two different "across": slot attention attends across patches inside one frame (to make the objects); the C-JEPA transformer attends across all slots in all frames (to learn dynamics).
Q4. How does the masking work — cross-attention?

No. Nothing is erased from the image either. Masking is replacing vectors in the token list, like BERT with objects instead of words:

           f1    f2   f3   f4   f5   f6 | f7 ... f16
cube      real   M    M    M    M    M  | M  ...  M      ← chosen object
ball      real  real real real real real| M  ...  M
...(other 5 slots like ball)            | future: all M

One bidirectional self-attention transformer reads all 112 tokens at once. A masked cube token at f4 can look at the ball at f3–f5. The output is read only at masked positions. Because the cube's own past is hidden, the model cannot just copy its motion; it has to use the other objects — this is the "interaction" bias.

Compare: MAE drops masked patches; I-JEPA / V-JEPA mask patches or blocks; C-JEPA masks whole objects and keeps placeholders.

Q5. So the vision tokens change from patches × frames to slots × frames?

Yes, that is the main change.

Patch-based (DINO-WM, V-JEPA)C-JEPA
tokens per frame196 patches, 384-d4–7 slots (+ aux), 128-d
Push-T size per step196 × 384 = 75,264 numbers6 × 128 = 768 (~1%)
one token meansa square of the imageone object
masking one tokenhides part of an object, easy to guess from neighbourshides the whole object
  • Gain: much cheaper attention and planning; object masking becomes meaningful.
  • Loss: fine detail (Push-T: patches 91.3 vs slots 88.7); errors of the slot encoder pass straight through; N is fixed per dataset (choose max objects + 1).
  • One training sample is still one clip (frames × slots tokens), not one slot. More objects → more slots → cost grows with the square of the token count, but stays far below patches (16 × 196 = 3,136 tokens).
Link to other notes. FIOC-WM (Feng, Lippe & Magliacane, NeurIPS 2025, arXiv:2511.02225) also uses slot attention on DINOv2 and models interactions with an explicit graph. C-JEPA gets the interaction bias from masking instead of a graph, and cites FIOC-WM as related work.
