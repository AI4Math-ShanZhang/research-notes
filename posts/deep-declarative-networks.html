Deep Declarative Networks — a Layer Defined by "argmin"

Paper: Deep Declarative Networks: A New Hope — Stephen Gould, Richard Hartley & Dylan Campbell (ANU), TPAMI 2021, arXiv:1909.04866. Code: anucvml/ddn.

📄 Paper Summary

A normal layer gives an explicit forward function, like y = ReLU(Wx + b). A declarative node instead says what the output should satisfy: the output is the solution of an optimization problem,

y(x) = argminu f(x, u)  (optionally subject to constraints)

  • Forward: run any solver to find y. The paper calls these networks deep declarative networks (DDNs).
  • Backward: use the implicit function theorem at the solution. With no constraints, dy/dx = −(Huu)⁻¹ · Hux, where H are second derivatives of f. The paper also gives the gradients for equality and inequality constraints. The backward pass does not need to know how the solver worked, only the final y.
  • Normal layers are a special case (e.g. the mean is argmin Σ(u − xi)²), so DDNs include current deep models.
  • A PyTorch library lets declarative and normal layers live in the same network.
  • Experiments: robust pooling (Huber, Welsch, truncated quadratic, …) in place of max pooling for point cloud classification (ModelNet40 with added outliers), and projection onto L1 / L2 / L∞ balls/spheres as a layer in image classification (ImageNet).

🖊 My Key Notes

Notation

  • x — input to the layer (e.g. features from a CNN / PointNet).
  • u — a candidate output. The solver moves it around.
  • f(x, u) — the cost of picking u. Smaller is better. This is the layer's definition.
  • y — the layer output = the u with the smallest cost.
  • Huu, Hux — second derivatives of f (w.r.t. u twice; w.r.t. u then x).
  • W, L — the network weights and the training loss (e.g. cross-entropy). Not the same as f.

Running example: robust pooling on one feature channel, x = [1, 2, 3, 100] (100 is an outlier), with f(x, u) = Σ huber(u − xi), threshold 1.

Same answer. If a closed form exists (mean, L2 norm), just use autograd — the declarative view gives nothing extra.

Step 2 — When it matters: no formula for y

"Knowing f" is not "knowing a formula y = g(x)". Autograd can differentiate f, but not "argmin". Smallest example: define y by y⁵ + y = x. At x = 2, y = 1. There is no formula for y, but differentiate both sides w.r.t. x:

5y⁴ · dy/dx + dy/dx = 1   →   dy/dx = 1 / (5y⁴ + 1) = 1/6

Only the equation and the solution are needed. That is the implicit function theorem. In a DDN, the equation is the optimality condition ∂f/∂u = 0, and the solution comes from the solver.

  • Mean pooling: Σ(u − xi) = 0 solves by hand → formula → autograd.
  • Robust pooling: Σ clamp(u − xi, −1, 1) = 0 has no closed form → solver + IFT.

Step 4 — Forward: the solver is an inner loop

The solver is plain optimization code with no learned weights. It is not the CNN. It walks downhill on f: slope g(u) = Σ clamp(u − xi, −1, 1); slope > 0 → go left, slope < 0 → go right, slope = 0 → stop.

Gradient descent from the mean with step 1: 26.5 → 24.5 → … → 4.5 → 2.5, twelve steps, then the slope is 0. f is convex (one bowl, one bottom), so slope = 0 means the global minimum. For a non-convex f (e.g. truncated quadratic) the solver only finds a nearby minimum, and the start point matters.

You don't compute slopes by hand. You write objective; autograd gives the slope; any off-the-shelf optimizer moves u:

def objective(self, x, u):              # the layer's definition (you write this)
    return huber(u - x).sum()

def solve(self, x):                     # generic: works for any smooth objective
    u = x.mean().clone().requires_grad_()   # start point (a guess near the answer)
    opt = torch.optim.LBFGS([u])
    def closure():
        opt.zero_grad()
        loss = self.objective(x.detach(), u)  # x is fixed while searching
        loss.backward()                       # autograd computes the slope
        return loss
    for _ in range(20):
        opt.step(closure)
    return u.detach()

# gradient(): not written — the library applies −H_uu⁻¹·H_ux using autograd on objective

objective says what is good; solve says how to find it. They are split only so you can swap in a faster solver (closed form, Newton, sorting for L1 projection).

Step 5 — Backward: IFT at the solution

At y = 2.5: Huu = number of inliers (|y − xi| < 1) = 2 (the points 2 and 3); Huxi = −1 for inliers, 0 for the others. So

dy/dx = −H_uu⁻¹ · H_ux = [0, 1/2, 1/2, 0]

The outlier 100 gets zero gradient, so it sends no error signal back to the backbone.

Step 6 — Why not just backprop through the solver steps (unrolling)?

In the 12 steps above every clamp is saturated at ±1, so the slope is a constant 2 and has zero derivative. Autograd therefore records only y = mean(x) − 2·12, and gives

unrolled:  dy/dx = [1/4, 1/4, 1/4, 1/4]     # outlier gets 1/4 — wrong
IFT:       dy/dx = [0,   1/2, 1/2, 0  ]     # true derivative of the solution
  • Correctness: unrolling differentiates the path (start, step size, stop step), not the answer.
  • Memory: unrolling stores every step; IFT needs only the final y, whatever the number of steps.
  • Any solver: sorting, if/break, scipy, C++ or QP solvers can't be backpropagated through — with IFT that does not matter.

Step 7 — Two loops: f is not the loss, u is not a parameter

training step:
  forward:
    x    = CNN_W(input)                        # e.g. PointNet per-point features
    inner loop: solver moves u until f is smallest  →  y = u      # per input, no labels
    pred = MLP_W(y)
    L    = cross_entropy(pred, label)          # e.g. "chair" 0.7 → L ≈ 0.36
  backward:
    L → y   normal autograd
    y → x   IFT (not through the inner-loop steps)
    x → W   normal autograd
  outer loop: SGD / Adam updates W

Step 8 — Where this shows up (and the link to loop transformers)

Standard CNN / Transformer layers are all explicit (y = MLP(x), y = Attn(x)), so they never need this. Declarative layers appear when the output is defined by a condition:

  • Deep Equilibrium Models (DEQ): loop one transformer block until it stops changing, y = Layer(y, x). The fixed point has no formula; backward uses IFT with memory independent of loop count. A looped transformer run to convergence is a DEQ — this is the bridge to this category.
  • MetaOptNet: few-shot head = an SVM solved per task with a QP solver.
  • 3D geometry: PnP / ICP / bundle adjustment (e.g. EPro-PnP).
  • Matching: optimal transport via Sinkhorn.
  • Control: differentiable MPC.

Honesty section

  • Niche: no benefit for layers with a closed form, which is almost every layer in mainstream nets.
  • Cost: the forward pass runs a solver per input; the backward pass inverts Huu, which is expensive when the output is large (hand-written gradients help when Huu has a simple form, like "count the inliers").
  • The gradient can fail to exist when f is non-smooth or the solution is not unique; non-convex f gives a local minimum that depends on the start point.
  • Related tooling: cvxpylayers (convex problems — no solver or gradient to write), Theseus (non-linear least squares), JAXopt custom_root (same IFT idea).
Takeaway. A declarative layer is "output = the u with the lowest cost f(x, u)". You write f; a generic solver finds y in an inner loop; the backward pass uses the implicit function theorem at y instead of unrolling the solver, which gives the correct gradient (outlier → 0, not 1/4) with memory independent of the solver's steps. It only matters when y has no formula — e.g. a fixed point of a looped block (DEQ).
